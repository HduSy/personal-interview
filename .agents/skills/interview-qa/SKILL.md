# Interview QA：面试问答卡片生成器

把一道面试题变成一张可复习的问答卡片：上半部分是可精读的 LLM 标准答案；下半部分「你的回答」是你自己的口述——读完标准答案用自己的话讲一遍才算真正掌握（费曼学习法），讲完回填，不满意可以反复重讲。每题一个文件，按主题归入分类文件夹，编号分类内递增，攒成题库。

## 卡片结构：三部分

每张卡片固定为三个一级标题，顺序不可变：

```markdown
# NN. 题目

## 高频问答
### ...

## 加深理解
### ...

## 你的回答
### 口述点评
```

| 部分 | 内容 | 是否必需 |
| --- | --- | --- |
| `## 高频问答` | 面试时直接说出口的答案 + 1–3 个高频追问 | 必需 |
| `## 加深理解` | 推导、计算、边界与例外、易混辨析等自学内容 | 无内容时可省略 |
| `## 你的回答` | 用户口述与点评 | 必需 |

页面标题是唯一的 `#`；三部分是 `##`；其下用 `###` 及以下。层级必须连续，不允许跳级。

## Workflow

### 1. 定位目标文件夹

- 用户在指令里给了文件夹 → 直接用。
- 没给 → 用 AskUserQuestion 问一次；同一会话后续题目沿用该文件夹，不再重复问。
- 文件夹不存在时随首次写文件自动创建。

### 2. 新题还是同题再入？

- 在题库里找同主题已有卡片：按题目语义匹配（同一概念的不同问法也算同题，如「讲讲事件循环」和「事件循环是什么」），不限精确文件名。
- 找到 → 按「同题再入：先判断诉求」一节处理，不走下面 3-5 步。
- 没找到 → 新题，继续。

### 3. 归类到分类文件夹

- 列出题库根目录下的一级子文件夹。
- 题目类型与某个已有子文件夹明确匹配（如「解释HTML语义化」→ `html/`）→ 直接归入，不用问。
- 没有匹配或拿不准 → **不擅自新建文件夹**，用 AskUserQuestion 给出建议选项，用户确认后再动：
  - 最接近的已有子文件夹（若有）。
  - 2-3 个基于题目主题建议的新文件夹名（小写英文短词，如 `browser/`、`network/`、`algorithm/`）。
  - 用户可通过自定义输入命名新文件夹。
- 题库还没有任何子文件夹时同样先问：给建议分类名让用户选或自定义。
- 只归到一级子文件夹，不做多级分类。

### 4. 确定编号与文件名

- 编号按分类文件夹各自计数：只扫描题目所属分类文件夹内形如 `NN-*.md` 的文件，取最大 NN，下一题 = NN + 1；该分类为空则从 `01` 开始，两位数字补零。
- 无数字前缀的文件不参与计数。
- 文件名：`{NN}-{题目}.md`，写入 `{题库根目录}/{分类}/`；题目可保留中文，去掉不适合做文件名的字符（`/ : ? *` 等），过长时截断到 40 字以内。例：`html/02-解释HTML语义化.md`。

### 5. 生成卡片并写文件

- 按下方两部分规范生成完整内容：「高频问答」与「加深理解」是标准答案，「你的回答」是用户口述——用户消息里已带自己的表述就直接填入，没有就留待口述占位。
- Write 到目标文件，然后在对话中完整展示卡片内容并告知文件路径。

## 同题再入：先判断诉求

用户再次提到已有卡片的问题时，输入可能是两种性质完全不同的东西，先判断再动手：

**A. 用户口述（费曼式表述）**——在「讲」不在「问」：第一人称陈述自己对概念的理解。
→ 完全替换「你的回答」整节，只动「你的回答」，不碰前两部分。用户可能表述不满意、掌握不熟练而多次重讲，每轮整节覆盖。口述原样保留，不润色、不替换用词，至多做最轻排版（分段、序号）。同时更新「口述点评」小节：评分（`评分：X/10`）+ 一句总体准确度 + 2-4 条缺口（遗漏的关键点、说得不准的地方、值得补的例子），点评跟着口述走，每轮一并覆盖。

**B. 疑问 / 困惑 / 修改要求**——在「问」或在「指」：对概念有困惑、指出正文有误、要求补充或精简。
→ 按内容归位，不要一律塞进正文：
- **概念疑问、原理推导、边界讨论** → 写入「加深理解」（见下一节），不进正文。
- **事实错误** → 直接修正正文。
- **表述冗余** → 精简正文。
- **确实属于面试作答范围的新内容** → 才补进正文，小节编号顺延。

改完在对话里说明改了哪里、写到了哪一节。

**C. 拿不准是 A 还是 B** → 用 AskUserQuestion 问一句再动手，宁可多问，不猜错方向。

## 高频问答规范

- 页面标题 `# {NN}. {题目}`，其下是 `## 高频问答`。
- `## 高频问答` 内用 `### 1.` `### 2.` … 组织，2–5 个小节；常见骨架是「是什么 → 核心机制 → 怎么用 → 对比 / 边界 → 高频追问」。
- 内容形态跟着题目走，不硬套模板：
  - 概念对比类 → 优先用叙述 + 分组列表——面试是口述，列表的每一条要能按顺序说出口；表格只用于「速查/枚举」性质的收尾材料（结果对照、版本清单、API 分类），不承担主要讲解。
  - 代码手写类 → 直接代码块 + 逐段讲解，不硬凑三段论。
  - 原理机制类 → 分层 / 分步讲解。
  - 方法论 / 案例类（产品、运营等岗常见）→ 框架拆解 + 案例佐证，不硬凑代码和原理。
- 关键术语首次出现加粗；代码用 fenced code block 并标注语言。
- **正文只写面试要说的**：面试时不会说出口的推导过程、规范出处、实现细节、历史沿革，一律不放正文，需要时写进「加深理解」。

### 表述风格：专业直抒，不比喻

- **禁止比喻和类比**。不写「就像一个快递员」「可以想象成」「好比」「类似于……一样」这类句子。技术概念用**术语定义 + 机制解释**，不靠打比方辅助理解。
- **禁止自造名词**。可以分层、分阶段讲解，但不发明「五棵树」「三驾马车」这类听起来像业界术语的自造说法。正文中出现的每个专有名词，都必须能在规范、MDN 或浏览器实现文档里找到出处；查不到出处的说法，要么改成普通描述，要么删掉。
- **少用行话，说人话**。能用大白话讲清的概念，不引入教科书式术语（如「约束变量」这类对仗词）；必须使用的术语，在首次出现处就地用一句话解释。目标是读者秒懂，不是显得专业——术语堆砌优先删。
- **直抒优先**：先给结论或定义，再展开机制。不写铺垫式开场（「在说这个之前，我们先来看看……」），直接进入正题。
- **区分事实与记忆法**：口诀、助记只能放在小节末尾，且要明确标注是记忆方法，不冒充标准术语。
- **表述留边界**：有把握的直接陈述，不确定的写清适用前提（「在 X 条件下」「主流浏览器中」「早期规范如此」），不用「应该是」「可能吧」这类模糊词。
- **不引用规范条文编号**：正文不出现「§10.3.7」「CSS 2.1」「WCAG 2.1」「RFC 9110」这类章节号或标准编号，也不贴英文原文。需要说明依据时用「规范规定」「无障碍规范要求」这类泛称即可。查证在工作过程中完成，结果不写进卡片。

### 卡片间引用：单向链接，不回写

- 正文提到题库已有卡片讲过的知识点时（习惯写法「xx 题里讲过」），把指代词写成指向该卡路由的链接：`[相等比较题](/javascript/09-loose-vs-strict-equality)`，不用裸文字。链接文字用自然简称即可，不必抄全题号。
- 路由 = `/分类/文件名`（去掉 `.mdx`），与各分类 `index.mdx` 里的链接一致。
- 引用是**单向**的：新卡指向旧卡；不在旧卡里回写「被谁引用」，也不设「相关卡片」区块——需要反查时 grep 全库，不进卡片内容。
- 知识点没有对应卡片时照旧裸描述，不为引用预建空卡。

### 可视化组件：需要效果就用沙箱

项目内置三个组件，统一从 `../../components` 引入：

```mdx
import { Sandpack } from '../../components';
```

- **`<Sandpack>`**：可交互代码沙箱。凡是「运行后能看到效果差异」的内容——布局效果、`min-width: 0` 这类行为差异、事件循环、DOM 操作——**必须用沙箱演示，不能只贴静态代码块**。
  - 快捷写法：`html` / `css` / `js` 三个属性直接传字符串，`template` 默认 `static` 即可，无需自己拼 `files`。
  - 需要对比时，在同一个沙箱里放多组结构，用注释或标签标明差异点。
  - JS 相关题目加 `showConsole`，把输出打到控制台。
- **`<Mermaid>`**：流程图、时序图、决策树。每张卡最多 1 个。
- **`<Excalidraw>`**：需要手绘风格示意图时使用。

判断标准：**只说语法规则时用代码块；需要看到结果时用沙箱。**

### 篇幅：长话短说

- **正文只写面试官最想听的**：每一节正面回答考官这个问号——是什么、怎么做、为什么——再补一句支撑。按评分点组织，不做知识扩展。
- **正文要预判追问**：每题写完后自问「考官接下来最可能问什么」，把 1–3 个高频追问连同答案直接写进正文，作为独立小节或该节收尾。面试官会问到、而正文没答的，属于漏答。
- **不绕圈子**：不写「这个问题要分几个方面看」之类的铺垫，不先讲背景和历史，第一句就给结论。
- **小节开头直接给答案**：第一句就是面试时能说出口的结论，不做铺垫、不先讲原理。
- **原理只保留「能用得上」的部分**：解释到「知道怎么写、知道什么时候会失效」即可，推导过程、规范出处、历史演进一律不写。面试是限时作答，不是写教材。
- **每个二级小节正文控制在 300 字以内**（不含代码块与表格）。超出时优先删**推导过程**，保留**结论与成立条件**。
- 同一知识点只讲一遍：正文讲过的，不在表格、示例、补充说明里再复述。
- **「高频问答」部分正文（不含代码与表格）控制在 2000 字以内**。

**删什么**：推导与演算过程、规范出处与标准编号、历史演进与兼容性沿革、重复解释、「补充」「进阶」「高频追问」类的大段外延内容、自问自答式的铺垫。

**留什么**：能直接说出口的结论、代码示例、对比表、失效条件与边界、面试官会追问的关键差异。

**判断标准**：写完自问「这段面试时会不会说出口」。不会说的，删掉或压成一句。

**成稿自检**：把每节第一句连起来读——应当能独立构成一份完整回答。若读起来像目录或背景介绍，说明没答到考官的问题上，重写。

## 加深理解规范：自学用的补充区

「高频问答」回答「面试怎么说」，「加深理解」回答「我为什么没想明白」。两者分开，别混在一起。

- **位置**：紧随「高频问答」之后，标题固定为 `## 加深理解`。
- **内容**：原理追问的答案、概念辨析、边界与例外、踩坑记录、计算过程的推演。这些面试时不会说出口，只为看懂和记牢服务。
- **触发时机**：对话中提出疑问、我纠正了错误、或解释了衍生概念时，把结论归档到这里。
- **写法**：`### 一句话问题` + 简明解答，一问一条，每条 300 字以内。没有内容时整节不写。
- **不进正文**：推导过程、术语来源、实现细节、历史沿革、兼容性沿革，一律写在这里而不是正文。
- **边界**：面试官可能追问的，放正文；只有自己学明白才需要的推演与冷门边界，放答疑。两者冲突时，以「考官会不会问」为准。

正文与答疑的判断标准：**这句面试时会不会说出口？说，进正文；不说，进答疑。**

## 你的回答规范

- 结构固定：`## 你的回答`，其下 `### 口述点评`。
- 「你的回答」是用户自己的口述（费曼学习法：能用自己的话讲出来才算真正掌握），LLM 不代写、不示范。
- 「口述点评」是 LLM 对口述的反馈，格式：`评分：X/10`（10 分制，按关键点覆盖度与准确性打分）→ 一句总体准确度 → 2-4 条缺口（遗漏的关键点、说得不准的地方、值得补的例子）。语气就事论事：讲对的一句带过，重点放缺口，不堆客套；评分同样不客套——有明显缺口就给中间分，不人均高分。
- 新建卡片时用户还没口述 → 「你的回答」留占位：`（待口述：读完上面的标准答案，用自己的话讲一遍发给我，我帮你填进来）`，点评小节暂不出现。
- 用户发来口述 → 原样填入或整节替换：保留用户的原始说法，不润色、不替换用词，至多做最轻排版（分段、序号），点评同步更新。
- 用户可能多轮重讲，口述和点评每轮一并覆盖，不保留旧版本。

## 质量红线

- 技术事实必须准确；没把握的结论先查证，不编造。
- 不写比喻、类比、拟人化的说明；概念用术语和机制直述。此规则同样适用于「口述点评」——点评直接指出对错与缺口，不靠修辞。
- 不自造听起来像业界术语的名词；专有名词必须可追溯出处，自创的助记法要标明是助记法。
- 少用表格：面试靠口述，表格结构说不出口，正文讲解一律叙述 + 列表。仅枚举/速查性质的内容（全量对照、版本线、mutation 分类清单）可用表格，单卡一般不超过一个，且不放在小节开头当总览。
- 目标文件名已存在时不覆盖，换下一个编号并在回复中说明。
- 用户一次给多道题时，逐题按编号生成、逐题存文件。
- 不擅自创建新的分类文件夹——新建分类必须经用户确认（选建议项或自定义命名）后进行。
- 同题再入先判断诉求（口述替换还是疑问优化），拿不准先问，不猜方向。
- 用户口述原样入卡，不改写、不润色。

## 边界（不处理）

- 模拟面试官连续追问、多轮 mock 面试 → 正常对话回答，不进题库。
- 简历相关 → tailored-resume-generator。
- 非面试场景的普通知识提问 → 直接回答，不触发本 skill。
- 行为面试 / HR 面问题（个人经历类，无标准答案）→ 不在范围内，直接对话给建议。
