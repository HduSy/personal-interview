# 01. src 与 href 的区别

## 核心区别

* **`src`（Source）**：用于**替换 / 嵌入**。指向的外部资源会下载并嵌入到当前文档所在位置，成为文档的一部分。  
  *常见标签*：`<script>`、`<img>`、`<iframe>`。
* **`href`（Hypertext Reference）**：用于**建立联系**。在当前文档与目标资源之间建立超链接或关联关系，不会替换当前标签。  
  *常见标签*：`<link rel="stylesheet">`、`<a>`。

---

## 阻塞机制说明

> **澄清误区**：“图片和框架等元素在处理时也会暂停其他资源的下载和处理”是**错误**的。

* **图片（`<img>`）**：**完全异步加载**。不阻塞 DOM 解析，也不阻止其他资源下载。仅在加载完成后可能触发回流/重绘，并延迟 `window.onload`。
* **框架（`<iframe>`）**：**异步加载**。不阻塞主页面 DOM 解析，但会阻塞父页面的 `window.onload`，开销较大。
* **脚本（`<script>`）**：普通同步脚本会**阻塞 DOM 解析**（因为脚本可能修改 DOM），但现代浏览器的预加载扫描器（Preload Scanner）依然会在后台并发下载后续资源。可通过 `defer` 或 `async` 实现异步非阻塞加载。

---

## 对比总结

| 资源标签 | 属性 | 是否阻塞 DOM 解析？ | 是否阻塞后续并发下载？ | 关键影响 |
| :--- | :--- | :--- | :--- | :--- |
| `<script src="...">` | `src` | **是** | 否（后台并发拉取） | 延迟 `DOMContentLoaded` |
| `<img src="...">` | `src` | **否** | 否 | 仅延迟 `window.onload` |
| `<iframe src="...">` | `src` | **否** | 否 | 延迟父页面 `window.onload` |
| `<link rel="stylesheet">`| `href` | **否** | 否 | 阻塞渲染树生成与后续 JS 执行 |
