# 01. src 与 href 的区别及其加载机制

## 面试标准回答

### 1. 核心定义与本质区别

* **`src`（Source，源）**：
  * **作用**：指向外部资源的位置，其目的是将外部资源**替换/嵌入**到当前标签所在的位置。
  * **典型标签**：`<script src="...">`、`<img src="...">`、`<iframe src="...">`、`<video src="...">`。
  * **表现形式**：浏览器解析到该标签时，会根据 `src` 指向的地址下载对应资源，并将其作为当前文档内容的一部分进行处理。

* **`href`（Hypertext Reference，超文本引用）**：
  * **作用**：指向网络资源的位置，用于在**当前文档与目标引用资源之间确立联系**。
  * **典型标签**：`<link href="...">`、`<a href="...">`。
  * **表现形式**：它只是建立一种关联关系（如引用外部样式表或提供跳转锚点），而不是直接把外部资源替换到当前标签处。

### 2. 澄清误区：img / iframe 会阻塞页面解析或下载吗？

> **原题误区分析**：  
> 原说法认为 *“当解析到该元素时，会暂停其他资源的下载和处理，图片和框架等元素也如此”* —— **这是完全错误的以讹传讹**。

#### ① 图片（`<img>`）
* **完全异步加载，不阻塞 DOM 解析**：浏览器遇到 `<img>` 时会发起异步请求，主解析线程**继续向下解析 DOM 树**，绝不会停下来等待图片下载。
* **对渲染与性能的影响**：
  * 图片下载完成前，若未在 HTML/CSS 中显式指定宽高（`width` / `height` 或 `aspect-ratio`），图片加载完成后可能会触发**回流（Reflow）与重绘（Repaint）**，引发累积布局偏移（CLS）。
  * 图片会阻塞 `window.onload` 事件的触发，但**不阻塞 `DOMContentLoaded`**。

#### ② 框架（`<iframe>`）
* **同样异步加载，不阻塞父文档 DOM 解析**。
* **开销与影响**：`<iframe>` 相当于一个嵌套的独立浏览上下文，虽然不阻塞主文档 DOM 构建，但会**阻塞父页面的 `window.onload`**，并且消耗较多内存与 HTTP 连接并发数。

#### ③ 脚本（`<script>`）
* **默认阻塞 HTML 解析**：普通同步 `<script>` 在遇到时，解析器必须暂停 DOM 解析，等待该脚本下载并执行完成（因为 JS 可能会执行 `document.write` 或操作 DOM）。
* **现代浏览器的并发优化（预加载扫描器 Preload Scanner）**：  
  即使主线程被 `<script>` 阻塞，现代浏览器的**预加载扫描线程**依然会提前扫描后续 HTML，**并发下载**后续的 CSS、JS 和图片资源，因此现代浏览器中并不会“暂停所有其他资源的下载”。
* **异步优化属性**：
  * `defer`：异步下载，待 DOM 解析完成之后、`DOMContentLoaded` 事件之前按原顺序执行。
  * `async`：异步下载，下载完成后立刻暂停解析并执行，执行顺序无序。

### 3. 各种资源标签的阻塞机制对照表

| 标签类型 | 代表元素 | 是否阻塞 HTML 解析 (DOM 构建)？ | 是否阻塞后续资源并发下载？ | 阻塞阶段 / 关键影响 |
| :--- | :--- | :--- | :--- | :--- |
| **同步脚本** | `<script src="app.js">` | **是**（下载+执行均阻塞） | **否**（预加载扫描器后台并发拉取） | 延迟 `DOMContentLoaded` |
| **异步脚本** | `<script defer src="...">` | **否** | **否** | DOM 构建完毕后执行 |
| **图片资源** | `<img src="pic.jpg">` | **否**（异步非阻塞） | **否** | 仅延迟 `window.onload`，无宽高时引发布局抖动 |
| **框架元素** | `<iframe src="...">` | **否**（异步非阻塞） | **否** | 延迟父页面的 `window.onload`，独占上下文开销 |
| **样式表** | `<link rel="stylesheet">` | **否**（不阻塞 DOM 构建） | **否** | **阻塞渲染树（RenderTree）生成与后续 JS 执行** |

---

### 4. 满分口述总结（1 分钟速记）

> “`src` 和 `href` 最本质的区别在于**资源与当前文档的关系**：
>
> 1. **`src` 表示嵌入和替换**，指向的资源是当前页面内容的一部分，如 `script`、`img` 和 `iframe`；
> 2. **`href` 表示引用和建立联系**，用于当前文档与外部资源之间建立超链接，如 `link` 和 `a` 标签。
> 
> 针对阻塞问题，需要澄清一个常见误区：**只有未加 async/defer 的同步 script 会阻塞 DOM 解析；而 img 和 iframe 全是异步加载的，绝不会阻塞 HTML 解析或其他资源的下载**。它们只会在加载完成后影响 `window.onload` 或触发页面重排。同时，在现代浏览器中，即使遇到了同步脚本，后台的**预加载扫描器**也会并发下载后续资源，而不会串行停滞。”
