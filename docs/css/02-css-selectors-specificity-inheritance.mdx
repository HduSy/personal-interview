# 02. CSS 选择器有哪些？优先级？哪些属性可以继承？

## 1. CSS 选择器全景分类

CSS 选择器是浏览器匹配 DOM 树节点并应用样式的规则。在现代 CSS 规范中，选择器主要划分为以下五大类：

### (1) 基础与关系选择器

| 类型 | 语法示例 | 匹配规则说明 |
| --- | --- | --- |
| **通配符选择器** | `*` | 匹配页面中的所有 HTML 元素（性能消耗相对较高） |
| **元素 / 标签选择器** | `div`, `p`, `span` | 匹配所有对应的 HTML 标签名 |
| **类选择器** | `.btn`, `.card` | 匹配包含对应 `class` 属性值的元素 |
| **ID 选择器** | `#header`, `#app` | 匹配具有特定唯一 `id` 属性值的元素 |
| **并集 / 分组选择器** | `h1, h2, .title` | **逗号分隔**，将相同的样式规则同时应用于多个不同的选择器目标 |
| **后代选择器** | `nav a` | 匹配 `nav` 内部**任意层级**的所有 `<a>` 元素（空格连接） |
| **子代选择器** | `ul > li` | 仅匹配 `ul` 的**第一代直接子元素** `<li>` |
| **相邻兄弟选择器** | `h2 + p` | 紧跟在 `h2` 后面且与其同级的**第一个** `<p>` 元素 |
| **通用兄弟选择器** | `h2 ~ p` | 位于 `h2` 之后且与其同级的**所有** `<p>` 兄弟元素 |

> ⚠️ **分组选择器的经典避坑考点（连带失效陷阱）**：  
> 在传统的逗号选择器列表中，**只要其中任意一个选择器不被当前浏览器识别或语法非法，整条规则全部失效！**  
> 例如：`h1, ::-webkit-scrollbar { color: red; }` 在 Firefox 下会直接导致 `h1` 也无法变红；现代 CSS 推荐用宽松容错匹配的 `:is(h1, ::-webkit-scrollbar)` 来规避此问题。

### (2) 属性选择器（Attribute Selectors）

| 语法 | 说明 | 示例场景 |
| --- | --- | --- |
| `[attr]` | 拥有该属性即可 | `input[disabled]`（禁用状态输入框） |
| `[attr="val"]` | 属性值完全等于指定值 | `input[type="text"]`（文本输入框） |
| `[attr^="val"]` | 属性值以指定字符串**开头** | `a[href^="https://"]`（外部安全链接） |
| `[attr$="val"]` | 属性值以指定字符串**结尾** | `a[href$=".pdf"]`（匹配 PDF 下载链接） |
| `[attr*="val"]` | 属性值包含指定**子串** | `img[src*="avatar"]`（头像相关图片） |
| `[attr~="val"]` | 包含以空格分隔的独立单词 | `[class~="active"]` |

### (3) 伪类（Pseudo-classes）与伪元素（Pseudo-elements）

> 💡 **核心区别口诀**：**伪类选的是「状态或已有节点」，单冒号 `:`**；**伪元素选的是「抽象生成的虚拟节点」，双冒号 `::`**（CSS2 曾允许伪元素单冒号，现代标准推荐双冒号区分）。

- **状态与结构伪类**：
  - 链接/交互状态：`:link`, `:visited`, `:hover`, `:active`, `:focus`, `:focus-visible`；
  - 表单状态：`:checked`, `:disabled`, `:required`, `:valid`；
  - 树结构伪类：`:first-child`, `:last-child`, `:nth-child(n)`, `:nth-of-type(n)`, `:empty`, `:root`；
  - 现代逻辑伪类（高频）：`:not()`, `:is()`, `:where()`, `:has()`（父选择器）。
- **常用伪元素**：
  - `::before` / `::after`：在元素内容的前后插入装饰性生成的伪元素（必须配合 `content` 属性）；
  - `::first-letter` / `::first-line`：匹配文本的首字首行；
  - `::placeholder`：匹配输入框占位符样式；
  - `::selection`：匹配用户用鼠标高亮选中的文本区域。

## 2. 选择器优先级与权重（Specificity）计算规则

当多个选择器同时选中同一个元素并设置了同一样式属性时，浏览器依据**权重（特异性）机制**决定谁最终生效。

### (1) 四元组权重体系：(Inline, ID, Class, Element)

CSS 权重由 4 个独立的计数位组成，记为 `(a, b, c, d)`：

| 级别 | 对应的选择器成分 | 单个权重值 |
| :---: | --- | :---: |
| **a** | **内联样式（Inline Styles）**：`<div style="...">` | `(1, 0, 0, 0)` |
| **b** | **ID 选择器**：`#main`, `#nav` | `(0, 1, 0, 0)` |
| **c** | **类选择器、属性选择器、伪类**：`.box`, `[type="text"]`, `:hover` | `(0, 0, 1, 0)` |
| **d** | **元素选择器、伪元素**：`div`, `p`, `::before` | `(0, 0, 0, 1)` |
| **无** | **通配符（`*`）、组合符（`+`, `>`, `~`）** | `(0, 0, 0, 0)` |

### (2) 权重的比拼规则与 3 大避坑硬核考点

1. **从左到右逐位比较，高位一票否决**：
   - 比较规则类似于版本号对比（如 `1.0.0.0` vs `0.9.9.9`）：优先对比最高位 `a`，若 `a` 大则直接胜出；若相同再对比 `b`，以此类推。
   - ⚠️ **辟谣（高频考点）**：**权重绝对不是十进制进制进制累加！11 个类选择器 `(0, 0, 11, 0)` 也绝对不可能跨位战胜 1 个 ID 选择器 `(0, 1, 0, 0)`**。
2. **权重相同时，遵循“源码就近原则”**：
   - 当计算出的 `(a, b, c, d)` 权重完全一致时，**在 CSS 文件中后定义的样式覆盖先定义的样式**（与 HTML 中 class 属性里的书写顺序无关！）。
3. **`!important` 的特权**：
   - 挂有 `!important` 的声明拥有超越普通权重系统的最高优先级。
   - 两个同属性都有 `!important` 时，再回退比较它们各自的选择器四元组权重。
4. **现代逻辑伪类的权重规则（大厂高频）**：
   - **`:is()` / `:not()` / `:has()`**：自身不增加权重，其权重直接取**括号内候选选择器中权重最高的那个**（如 `:is(#id, .class)` 的权重等于 `#id` 即 `(0, 1, 0, 0)`）。
   - **`:where()`**：其权重**恒定为 `(0, 0, 0, 0)`**，专门用于设计极易被使用者覆盖的基础公共库/Reset 样式。

## 3. CSS 属性继承机制（Inheritance）

CSS 的部分属性具有“向后代自动传递”的特性，合理利用继承能极大地精简代码结构。

### (1) 可继承 vs 不可继承属性速查

| 类别 | 常见典型属性 | 为什么这么设计？ |
| --- | --- | --- |
| **可继承属性**<br/>（文本与文字排版） | • **字体系列**：`font-family`, `font-size`, `font-weight`, `line-height`<br/>• **文本系列**：`color`, `text-align`, `text-indent`, `letter-spacing`<br/>• **其他**：`visibility`, `cursor`, `list-style`, `quotes` | 保持文章、排版等层级的内容在阅读时具有一致的字体与排版风格，避免每个字级都反复声明 |
| **不可继承属性**<br/>（盒模型与空间布局） | • **盒模型**：`width`, `height`, `margin`, `padding`, `border`<br/>• **布局方式**：`display`, `flex`, `grid`, `float`, `clear`<br/>• **定位图层**：`position`, `top/bottom/left/right`, `z-index`<br/>• **背景视觉**：`background`, `overflow`, `transform`, `filter` | 盒模型和边框若被继承，会导致父元素加了个边框，所有子代孙代全都被套上边框，页面排版会彻底崩溃 |

> ⚠️ **高频注意点（opacity 与继承）**：  
> `opacity` 本身是**不可继承**的！但为什么父元素设 `opacity: 0.5`，子元素也变半透明了？  
> 因为浏览器将父元素作为一个整体图层（Render Layer）进行阿尔法通道合成渲染，子元素设置 `opacity: 1` 无法“挣脱”父级图层的半透明限制。

### (2) 继承与优先级的特殊交叉点

- **继承属性的权重为零**：元素从父级继承来的样式，其优先级比通配符选择器（`*`）还要低！
  ```css
  * { color: black; } /* 通配符权重 (0, 0, 0, 0) */
  body { color: blue; } /* body 显式赋值 */
  /* 结果：<p> 最终呈现为黑色！因为继承自 body 的优先级低于通配符 * */
  ```
- **四大控制继承的通用关键字**：
  - `inherit`：强制显式继承父元素对应属性的值（如 `border: inherit`）；
  - `initial`：强制恢复为 CSS 官方规范规定的初始缺省值；
  - `unset`：若该属性天生可继承，则等同于 `inherit`；若不可继承，则等同于 `initial`；
  - `revert`：回退到浏览器默认（User-Agent）样式表。
