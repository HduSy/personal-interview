# 04. 设备像素、CSS 像素、设备独立像素、DPR、PPI 之间的区别？

## 1. PPI 描述硬件密度，设备像素是硬件最小单位，DPR 是换算比例

PPI 描述硬件有多密，设备像素是硬件的最小单位，CSS 像素和设备独立像素是软件层的抽象单位，DPR 是设备像素与 CSS 像素之间的换算比例。

## 2. 硬件层：设备像素出厂固定，PPI 由分辨率和对角线尺寸算出

设备像素是屏幕硬件上的最小物理发光单元，出厂即固定，手机参数里的分辨率就是设备像素数量。PPI 是每英寸的物理像素数量，只描述硬件，与 CSS 无关。

```
PPI = 对角线上的像素数 ÷ 对角线的物理长度（英寸）
PPI = √(水平像素² + 垂直像素²) ÷ 屏幕对角线英寸数
```

例：24 英寸 1920×1080 显示器约 92 PPI，DPR = 1；6.1 英寸 1179×2556 手机约 461 PPI，DPR = 3。同尺寸屏幕像素越多，PPI 越高，画面越细腻。

对角线英寸是长度单位，不是面积；同样对角线长度下宽高比不同，实际面积也不同，越接近正方形面积越大。

## 3. CSS 像素是 Web 的逻辑像素，设备独立像素是跨平台抽象

CSS 像素是代码里写的 `px`，是抽象长度单位，不直接对应物理发光点；它按参考像素定义，目标是让同样的 `px` 在不同屏幕上看起来差不多大，换设备或浏览器缩放都会改变它与物理像素的比例。设备独立像素是与硬件解耦的抽象单位，保证相同数值在不同设备上物理尺寸接近，Android 的 `dp`（1dp = 1/160 英寸）、iOS 的 `pt` 都是它的实现。

在 Web 上，CSS 像素可以理解为设备独立像素的具体实现：100% 缩放下二者可视为 1:1，缩放后脱钩。

## 4. DPR 是设备像素与 CSS 像素的比值，随缩放变化

DPR 是设备像素与 CSS 像素的比值：

```
DPR = 设备像素 / CSS 像素   （只看一个方向）
```

`window.devicePixelRatio` 可读，普通屏为 1，Retina 屏为 2 或 3。DPR = 2 时，1 个 CSS 像素覆盖 2 × 2 = 4 个物理像素。DPR 会随浏览器缩放变化：DPR = 2 的屏幕上把页面放大到 200%，`devicePixelRatio` 会变成 4。高 PPI 屏幕上若 1 CSS 像素等于 1 设备像素，文字会过小；DPR 让 1 CSS 像素覆盖多个物理像素，既保证物理尺寸合理，又利用多出来的像素提升清晰度。DPR 与 PPI 相关，`DPR ≈ PPI / 基准密度`（Web 基准约 96，Android dp 基准 160），但最终由厂商和系统结合 PPI 与观看距离设定，不是严格计算。

## 5. 五个概念的对比

| 概念 | 所属层面 | 是否可变 | 由谁决定 | 单位 / 公式 |
| --- | --- | --- | --- | --- |
| **设备像素** | 硬件 | 固定 | 屏幕出厂规格 | 个 |
| **CSS 像素** | 软件 / 规范 | 随缩放变化 | 浏览器 | `px` |
| **设备独立像素** | 软件 / 平台抽象 | 基本固定 | 操作系统 / 平台 | `dp`（Android）、`pt`（iOS） |
| **DPR** | 换算比例 | 随缩放变化 | 浏览器 / 系统 | 设备像素 ÷ CSS 像素 |
| **PPI** | 硬件 | 固定 | 屏幕物理属性 | √(w² + h²) ÷ 对角线英寸 |

五个概念的串联关系是：屏幕尺寸和分辨率决定 PPI，系统据此设定 DPR；CSS 像素乘以 DPR 得到设备像素，再除以 PPI 得到物理尺寸。

## 6. 工程影响：1px 边框、图片、Canvas 和设计稿

DPR = 2 时 1 CSS 像素对应 2 个物理像素，1px 边框会显粗或显糊；要真正的 1 物理像素细线，可写 `0.5px`（部分浏览器支持），或用伪元素配合 `transform: scaleY(0.5)`。图片要按 DPR 提供 1x / 2x / 3x 资源，并用 `srcset` 让浏览器选择。Canvas 的 `width` / `height` 单位是设备像素，需按 DPR 放大缓冲区。750px 宽的 @2x 设计稿按 `750 ÷ 2 = 375px` 写 CSS 宽度，1125px 的 @3x 设计稿除以 3。

```js
function setupCanvas() {
  const dpr = window.devicePixelRatio;
  canvas.width = canvas.clientWidth * dpr;
  canvas.height = canvas.clientHeight * dpr;
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
}
window.addEventListener('resize', setupCanvas);
```

```css
@media (min-resolution: 2dppx) {
  /* DPR >= 2 时生效 */
}
```

`dppx` 是 DPR 的 CSS 单位。

## 7. 浏览器缩放改变 DPR，移动端捏合缩放通常不改变

页面缩放改变的是 1 个 CSS 像素映射到多少设备像素。屏幕的设备像素总数固定，放大后布局视口（CSS 像素）变小，浏览器必须让每个 CSS 像素占更多设备像素才能铺满屏幕，所以：

```
当前 devicePixelRatio = 硬件 DPR × 页面缩放倍数
```

因此放大页面会像屏幕变窄一样触发媒体查询，因为媒体查询判断的是 CSS 像素宽度。Canvas 若只在初始化时读取一次 DPR，用户缩放后会变糊，需要在 DPR 变化时重新设置缓冲区；`srcset` 图片也可能被重新选择。缩放 200% 时 1 CSS 像素等于 4 个设备像素，细线在视觉上会变粗。移动端双指捏合改变的是 `visualViewport.scale`，页面布局没有重新计算，DPR 通常不变。

| 类型 | 触发方式 | 对 `devicePixelRatio` 的影响 |
| --- | --- | --- |
| **页面缩放（page zoom）** | 桌面端 Ctrl/Cmd + / - | 会变，等于硬件 DPR × 缩放倍数 |
| **系统缩放** | 操作系统显示设置（如 Windows 125%） | 会变，属于硬件 DPR 的一部分 |
| **双指捏合（pinch zoom）** | 移动端手势 | 一般不变，变化的是 `visualViewport.scale` |

## 8. 易混点

- PPI 是硬件密度，DPR 是软件换算比例，两者相关但不等价。
- CSS 像素与设备独立像素只在缩放 100% 时 1:1，缩放后脱钩。
