# 05. 隐藏页面元素的方式有哪些？区别是什么？

## 1. 按隐藏发生的层分类

隐藏方式的差异来自隐藏发生在不同层。一个元素同时涉及 DOM 树、渲染树、无障碍树，以及渲染管线上的布局和绘制阶段。

| 层 | 类型 | 含义 | 隐藏它的手段 |
| --- | --- | --- | --- |
| **DOM 树** | 树 | 节点还在不在文档里 | `removeChild` / `v-if` 卸载 |
| **渲染树（Render Tree）** | 树 | 浏览器要不要为它生成盒子 | `display: none` |
| **布局（Layout）** | 阶段 | 它参不参与占位与排版 | `display: none`、`height: 0`、`position: absolute` |
| **绘制（Paint）** | 阶段 | 它画不画到屏幕上 | `visibility: hidden`、`opacity: 0` |
| **无障碍树（A11y Tree）** | 独立的一棵树 | 读屏软件能不能感知到它 | `display: none`、`visibility: hidden`、`aria-hidden` |

DOM 树、渲染树、无障碍树是标准叫法；布局与绘制是渲染阶段。

## 2. 核心对比

| 方式 | 占据文档流空间 | Tab 可聚焦 | 鼠标可命中 | 读屏可读 | 可过渡动画 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| `display: none` | ❌ | ❌ | ❌ | ❌ | ⚠️ 需 `allow-discrete` | 从渲染树移除，最彻底 |
| `visibility: hidden` | ✅ | ❌ | ❌ | ❌ | ✅ | 保留盒子，不绘制 |
| `opacity: 0` | ✅ | **✅** | **✅** | **✅** | ✅ | 透明但仍可交互，最易误用 |
| `position: absolute; left: -9999px` | ❌（脱离文档流） | ✅ | ❌（在视口外） | ✅ | ❌ | 视觉隐藏、语义保留 |
| `clip` / `clip-path` + 1px（`.sr-only`） | ❌（配合绝对定位） | ✅ | ❌（仅剩 1px 且被裁剪） | ✅ | ❌ | 无障碍标准写法 |
| `height: 0; overflow: hidden` | ❌（高度塌缩为 0） | **✅** | ❌（高度为 0，被裁掉） | ✅ | ✅ | 折叠动画常用，焦点管理有问题 |
| `transform: scale(0)` | ✅ | **✅** | ❌（视觉面积为 0） | ✅ | ✅ | 布局盒不变，仍在流中占位 |
| `hidden` 属性 | ❌ | ❌ | ❌ | ❌ | ⚠️ 需 `allow-discrete` | 等价 `display: none`，可被 CSS 覆盖 |
| `content-visibility: hidden` | ⚠️ 元素自身盒子仍在 | ❌ | ❌ | ❌ | ⚠️ | 跳过内容，保留渲染状态 |
| `aria-hidden="true"` | 不影响布局 | ✅ | ✅ | ❌ | — | 只管无障碍，不影响视觉 |

「Tab 可聚焦」和「鼠标可命中」必须分开看：`transform`、`overflow` 只影响绘制与命中测试，不影响焦点管理。只有 `display: none`、`visibility: hidden`、`inert` 会同时把元素移出焦点序列。

## 3. display: none 与 visibility: hidden

`display: none` 不生成盒子，完全退出渲染树：不占位、不绘制、不可交互、不进无障碍树，并触发重排，频繁切换时代价最高。父级 `display: none` 时子元素写 `display: block` 也无法显示。它默认不能过渡，现代可配合离散过渡：

```css
.panel {
  transition: opacity .3s, display .3s;
  transition-behavior: allow-discrete;
}
```

`visibility: hidden` 仍生成盒子并参与布局，只是不绘制，不可点击、不可聚焦、读屏不读，可以过渡；它会继承，子元素可以用 `visibility: visible` 覆盖回来：

```css
.parent { visibility: hidden; }
.parent .child { visibility: visible; }
```

## 4. opacity: 0

`opacity: 0` 的元素完整存在：占位、可点击、可聚焦、读屏正常朗读，是最平滑的可动画属性，做淡入淡出首选，但最易造成隐形按钮事故；它还会创建层叠上下文，可能让 `z-index` 表现异常。

`aria-hidden="true"` 只影响无障碍树，不影响视觉、鼠标命中和 Tab 聚焦。元素仍可聚焦却加了 `aria-hidden`，会出现焦点落在隐形内容上的缺陷，通常要与 CSS 隐藏成对使用。

## 5. .sr-only 与负偏移定位

`position: absolute; left: -9999px` 把元素移出视口，元素仍在无障碍树里、仍可聚焦、鼠标点不到，但已脱离文档流；父元素没有建立定位上下文时，它会以更远的祖先或初始包含块为参照。更稳定的标准写法是：

```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);        /* 兼容旧浏览器 */
  clip-path: inset(50%);         /* 现代写法 */
  white-space: nowrap;
  border: 0;
}
```

用途是给读屏用户提供视觉上看不到的补充文本，例如「跳转到主内容」链接、图标按钮的文字说明。

## 6. height: 0

`height: 0; overflow: hidden` 视觉上塌缩，内容仍在 DOM 与无障碍树里，子元素依然可聚焦，用户 Tab 到看不见的链接时页面会滚动跳动。需要配合 `visibility: hidden`、`inert` 或 JS 禁用。

```css
.collapsed { height: 0; overflow: hidden; transition: height .3s; }
```

## 7. transform: scale(0)

`transform` 属于绘制阶段，不参与布局计算：布局盒仍是原宽高，文档流占位不变；鼠标按变换后的几何形状做命中测试，面积为 0 就点不中；但 Tab 仍可聚焦、读屏仍可读。做弹窗缩放入场时通常配合 `visibility` 或 `inert`。

## 8. content-visibility: hidden

跳过的是内容渲染，元素自身盒子仍参与布局，padding、border 照常占位；子内容既不渲染也不参与尺寸计算，自动高度的元素会塌缩到只剩自身盒模型。它保留渲染状态，再次显示比重建更快，适合频繁切换的大块内容；代价是内容不进无障碍树、`Ctrl+F` 搜不到、不可聚焦。

`hidden="until-found"` 使用这套机制，因此既能隐藏，又能被页内查找命中。

## 9. HTML 侧方式

`<div hidden>` 的默认样式等价于 `display: none`。如果全局写了 `div { display: block; }`，`hidden` 会失效，这是「hidden 不生效」最常见的原因。

```css
/* CSS 会覆盖它 */
div { display: block; }
```

`hidden="until-found"` 的内容可被页内查找命中，搜到时会自动展开并触发 `beforematch` 事件，适合折叠面板、FAQ。

`<input type="hidden">` 不渲染、不可见，仅用于承载表单数据并随表单提交。`<template>` 的内容不渲染、不执行、保持惰性，本质是待用模板。
