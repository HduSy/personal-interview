# 07. 谈谈你对 BFC 的理解？

## 高频问答

### 1. 定义

BFC（Block Formatting Context，块级格式化上下文）是一块**独立的渲染区域**：内部的块级盒子按块级规则排列，内部布局与外部互不影响。

它解决的是布局作用域问题——区域内元素怎么排、怎么浮动，都不会溢出影响到区域外的元素。

### 2. 触发方式

以下情况会创建 BFC：

| 方式 | 典型写法 |
| --- | --- |
| 根元素 | `<html>` 本身就是 BFC |
| 浮动 | `float: left` / `right`（不为 `none`） |
| 绝对定位 | `position: absolute` / `fixed` |
| 行内块与表格 | `display: inline-block` / `table-cell` / `table-caption` |
| 溢出隐藏类 | `overflow: hidden` / `auto` / `scroll` / `clip`（不为 `visible`） |
| 专用值 | `display: flow-root` |
| 布局隔离 | `contain: layout` / `content` / `paint` |

`display: flex` / `grid` 的**容器**建立的是 flex / grid 格式化上下文，不是 BFC；它们的**子项**才各自形成独立格式化上下文。这一点常被混为一谈。

### 3. 内部布局规则

- 块级盒子在垂直方向依次排列，起点是包含块的顶部。
- 同一个 BFC 内相邻块级盒子的垂直 margin 会发生**塌陷**。
- 每个盒子的左外边距紧贴包含块的左边缘（LTR 方向）。
- BFC 区域**不与浮动元素重叠**。
- 计算高度时，**浮动子元素参与**父元素高度计算。

### 4. 三个典型用途

#### (1) 清除浮动造成的高度塌陷

```css
.parent { overflow: hidden; }   /* 或 display: flow-root */
.child  { float: left; }
```

浮动子元素脱离文档流，父元素计算高度时本会忽略它。父元素成为 BFC 后，浮动子元素参与高度计算，父元素被撑开。

#### (2) 阻止父子 margin 塌陷

```css
.parent { overflow: hidden; }   /* 成为 BFC */
.child  { margin-top: 20px; }   /* 不再穿透父元素，父元素顶部不再出现间隙 */
```

父元素不是 BFC 时，子元素的 `margin-top` 会与父元素塌陷，表现为父元素整体下移。

**注意**：BFC 只能阻断**父子**之间的塌陷。**兄弟之间**的 margin 塌陷发生在同一个 BFC 内，即使其中一个是 BFC 元素也照样塌陷。

#### (3) 实现自适应两栏布局

```css
.left  { float: left; width: 200px; }
.right { overflow: hidden; }    /* 成为 BFC，不与浮动重叠 */
```

普通块级元素会环绕浮动元素，文字跑到左侧栏下方。右侧成为 BFC 后不与浮动重叠，自动占据剩余宽度。

### 5. 现代写法与边界

`overflow: hidden` 是历史写法，副作用明显：会裁剪溢出的内容（下拉菜单、阴影、tooltip 被切掉），还会改变滚动行为。

**`display: flow-root` 是专门用来创建 BFC 的值**，不产生任何副作用，现代项目优先用它。浏览器支持较新，需要兼容老环境时再退回 `overflow: hidden`。

其他需要知道的边界：

- `float` 和 `position: absolute` 虽然能创建 BFC，但会改变元素自身的布局方式，不应为了创建 BFC 而使用。
- BFC 是块级布局的概念，`display: inline-block` 创建的 BFC 会让元素变成行内块，宽度收缩、基线对齐等问题随之出现。
- `overflow: hidden` 的 BFC 效果对 `position: fixed` 的后代不生效——固定定位元素会跳过祖先的裁剪。
