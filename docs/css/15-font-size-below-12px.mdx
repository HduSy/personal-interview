# 15. 让 Chrome 支持小于 12px 的文字方式有哪些？区别？

## 高频问答

### 1. 为什么会有 12px 限制

Chrome 基于 Chromium 内核的简体中文版默认设了**最小字号 12px**：`font-size` 小于 12px 会被强制提升到 12px。这是早年为防止中文在小字号下无法辨认做的产品决策，属于浏览器设置而非 CSS 规范。

前提先说清：**Chrome 114 及之后版本已取消这个限制**（最小字号设置改为默认关闭）。这题主要是历史方案，但面试仍常问。

### 2. 五种方案

| 方案 | 写法 | 生效范围 | 主要缺点 |
| --- | --- | --- | --- |
| 缩放变换 | `transform: scale(0.8)` | 全平台 | 只缩视觉尺寸，**占位仍是原大小**；单独用会导致布局偏移，常需配合 `transform-origin` 和负 margin |
| 浏览器设置 | 设置 → 字号 → 最小字号调小 | 单台机器 | 不可控，不能要求用户改设置 |
| rem 技巧 | 根字号 + 相对单位换算 | 全平台 | 现代版本已无效；老版本里换算后的值仍会被钳制 |
| 图形替代 | SVG `<text>`、Canvas 绘字、图片 | 全平台 | 文本不可选中、不可搜索，SEO 与无障碍受损；维护成本高 |
| 字体覆盖 | 用本身就小的字体（如某些等宽字体 10px 设计） | 取决于字体 | 受字体资源约束，实际很少用 |

真正在代码里用的只有**缩放变换**一种，其余是理解层面的备选。

### 3. 推荐写法：scale + transform-origin

`scale` 缩小的是「绘制结果」，元素的布局盒不变，所以要处理占位偏移：

```css
.small-text {
  font-size: 12px;              /* 钳制值 */
  transform: scale(0.8333);     /* 12 × 0.8333 ≈ 10px 的视觉效果 */
  transform-origin: left top;   /* 从左上角缩，避免水平溢出 */
  display: inline-block;        /* transform 对行内元素不生效，必须先转块级 */
}
```

三个关键点：

- **必须 `display: inline-block`**：`transform` 不作用于非替换行内元素。
- **`transform-origin` 决定缩放锚点**：默认中心（`center`），文字会向两边收缩，与左右邻居产生间隙；`left top` 让缩放从左上角开始，占位逻辑可预测。
- **占位补齐**：布局盒仍是 12px 的宽度，需要视觉上紧凑排列时，用负 margin 抵消差值，例如 `margin-right: -2px`（按缩放比例计算）。

### 4. 各方案的本质区别

- **scale 是「视觉缩放」**：文字渲染成小字，但布局占位不变——所以必须处理锚点和 margin。它是唯一纯 CSS、全平台、可精确控制小数像素的方案。
- **浏览器设置是「放宽钳制」**：直接改规则本身，最干净，但属于用户侧配置，工程上不能依赖。
- **图形替代是「绕开 CSS」**：根本不走字体渲染管线，效果最可控，代价是文本语义全部丢失，可访问性上必须补 `aria-label` 或 `alt`。
- **rem 等相对单位不绕过钳制**：`0.833rem` 换算成 px 后仍小于 12px，照样被钳制，这是最常见的误区。

### 5. 高频追问

**小字号本身该不该用？** 不该为绕过限制而牺牲可读性。10px 以下的中文基本不可读，无障碍规范也要求正文不小于最小可读字号。这题的价值在理解渲染机制，不是鼓励写小字。

**新版 Chrome 怎么恢复小字支持？** Chrome 114 起最小字号默认不限制，直接写 `font-size: 10px` 即可；老版本的 macOS Safari、Firefox 从来没有这个限制。

**移动端呢？** 移动端 Chrome 同样受影响（老版本）。iOS WebView 无此限制。跨端方案里 `scale` 依旧是兜底写法。

## 加深理解

### 钳制发生在哪一层

最小字号不是 CSS 解析层丢弃声明，而是**字体选择与排版阶段**的钳制：声明值正常存入计算样式，浏览器在计算实际使用的字体尺寸时强制抬到最小值。这就是为什么 `getComputedStyle(el).fontSize` 返回的可能是 `12px` 而你写的是 `10px`——排查时用 Computed 面板能看到真实生效值。

### scale 方案的精确换算

目标视觉字号 ÷ 12 = scale 系数。要 10px 就是 `10/12 = 0.8333`，要 9px 就是 `0.75`。因为占位是 12px，垂直排列的多个小字元素之间会出现「行高比视觉字号大」的间距，需要同步缩小 `line-height` 或用负 margin 修正——这也是很多人觉得 scale 方案「布局难对齐」的原因。

### 为什么移动优先设计可以规避

如果设计系统允许，把「小字」改为「辅助信息用灰色、小间距」表达层级，而不是缩小字号，就不需要任何 hack。方案层面的取舍优于技术层面的绕过。
