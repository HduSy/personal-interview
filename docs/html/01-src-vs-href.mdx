# 01. src 与 href 的区别

## 核心区别

* **`src`（Source）**：**将外部资源嵌入/应用到当前文档**。  
  例如图片（`<img>`）属于 HTML 的**可替换元素**，浏览器会在后台异步下载并解码，用真实的图像内容**替换**掉当前标签的占位；脚本（`<script>`）则是将代码嵌入文档中并执行。
* **`href`（Hypertext Reference）**：**在当前文档与外部资源之间“建立关联”**。  
  例如样式表（`<link rel="stylesheet">`）引入样式规则，或超链接（`<a>`）提供跳转锚点，它只是建立关联网，**不会**替换标签自身的内容。

---

## 阻塞机制说明

> **澄清误区**：“图片和框架等元素在处理时也会暂停其他资源的下载和处理”是**错误**的。

* **图片（`<img>`）**：**完全异步加载**。不阻塞 DOM 解析，也不阻止其他资源下载。仅在加载完成后可能触发回流/重绘，并延迟 `window.onload`。
* **框架（`<iframe>`）**：**异步加载**。不阻塞主页面 DOM 解析，但会阻塞父页面的 `window.onload`，开销较大。
* **脚本（`<script>`）**：普通同步脚本会**阻塞 DOM 解析**（因为脚本可能修改 DOM），但现代浏览器的预加载扫描器依然会在后台并发下载后续资源；可通过 `defer` 或 `async` 变为非阻塞。

---

## 对比总结

| 资源标签 | 属性 | 是否阻塞 DOM 解析？ | 是否阻塞后续并发下载？ | 关键影响 |
| :--- | :--- | :--- | :--- | :--- |
| `<script src="...">` | `src`（嵌入） | **是** | 否（后台并发拉取） | 延迟 `DOMContentLoaded` |
| `<img src="...">` | `src`（替换） | **否** | 否 | 仅延迟 `window.onload` |
| `<iframe src="...">` | `src`（嵌入） | **否** | 否 | 延迟父页面 `window.onload` |
| `<link rel="stylesheet">` | `href`（关联） | **否** | 否 | 阻塞渲染树生成与后续 JS 执行 |
