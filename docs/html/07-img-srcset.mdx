# 07. img 的 srcset 属性的作用

## 1. 为什么需要 srcset？（解决响应式图片痛点）

传统的 `<img>` 标签只支持一个 `src` 属性，意味着所有设备只能加载同一张固定尺寸的图片：
- 在普通 1 倍屏（如普通 PC 显示器）上加载高分辨率大图，会**极大浪费网络带宽与流量**，拖慢首屏加载速度；
- 在高密度 Retina 高清屏（如 2 倍、3 倍屏移动设备）上加载低分辨率小图，图片会**出现边缘模糊和锯齿失真**。

为了实现真正的**响应式图片（Responsive Images）**，HTML5 为 `<img>` 标签引入了 **`srcset`** 属性，**允许开发者为同一图片元素提供一组不同分辨率或不同宽度的图片源列表，由浏览器根据当前设备的屏幕像素比（DPR）或视口宽度自主选择最合适的一张进行加载**。

## 2. srcset 的两种核心语法与工作机制

### 方式一：基于设备像素比（DPR）—— `x` 描述符

适用于**在页面中显示物理尺寸固定（如固定 100x100px 的头像、Logo、图标）**，但需要适配不同设备高清屏的场景。

```html
<img
  src="avatar-1x.png"
  srcset="avatar-1x.png 1x, avatar-2x.png 2x, avatar-3x.png 3x"
  alt="用户头像"
  width="100"
  height="100"
/>
```

- **工作机制**：
  - 普通普通屏（`window.devicePixelRatio === 1`）自动加载 `avatar-1x.png`；
  - 苹果 Retina 等 2 倍屏（`DPR === 2`）加载 `avatar-2x.png`；
  - 超高清移动端 3 倍屏（`DPR === 3`）加载 `avatar-3x.png`；
  - 不支持 `srcset` 的老旧浏览器自动回退到 `src`。

### 方式二：基于宽度与视口（结合 `sizes` 属性）—— `w` 描述符

适用于**图片显示尺寸随着屏幕视口宽度动态变化（弹性流式布局、栅格系统、Banner 横幅）**的场景。

```html
<img
  src="banner-800.jpg"
  srcset="
    banner-400.jpg  400w,
    banner-800.jpg  800w,
    banner-1200.jpg 1200w,
    banner-1600.jpg 1600w
  "
  sizes="(max-width: 600px) 100vw, (max-width: 1200px) 50vw, 800px"
  alt="活动横幅"
/>
```

- **参数解析**：
  - **`w` 描述符（图片真实物理像素宽度）**：告诉浏览器该图片的真实固有宽度，而非显示宽度（例如 `banner-800.jpg 800w` 表示该图实际文件宽 800 像素）。
  - **`sizes` 属性（布局意图通知）**：因为浏览器发起图片请求时还未开始渲染 CSS 样式，不知道图片最终在屏幕上会占多大，所以需要 `sizes` 预先告诉浏览器该图片在不同视口媒体查询下的**预期 CSS 显示宽度（逻辑像素）**。
- **浏览器决策流程（示例推演）**：

<Mermaid chart={`
flowchart LR
    A["1. 读取视口宽度<br/>(如 400px)"] --> B["2. 匹配 sizes 规则<br/>(100vw = 400px 逻辑宽)"]
    B --> C["3. 结合设备 DPR 换算<br/>(400px * DPR 2 = 800px)"]
    C --> D["4. 筛选 srcset 候选<br/>(匹配最接近且 >= 800w)"]
    D --> E["5. 精准发起网络下载<br/>(精准下载 800w 图片)"]
`} />

  1. **匹配 CSS 显示宽度**：假设用户在视口宽度为 400px 的手机上访问，命中 `(max-width: 600px)`，根据 `100vw` 算出图片在屏幕上的**预期显示宽度（CSS 逻辑像素）为 400px**；
  2. **换算物理像素需求**：获取设备像素比 DPR，若该手机为 Retina 2倍屏（`DPR === 2`），则填满这 400px 逻辑区域需要 **`400px * 2 = 800px` 的物理像素**才能清晰呈现；
  3. **筛选并下载图片**：从 `srcset` 候选列表中找出最接近且不小于 800px 的图片资源（精准匹配到 `banner-800.jpg 800w`）并发起下载。

## 3. srcset 与 `<picture>` 标签的区别与选型

两者同属于响应式图片规范，但解决的问题维度不同：

| 对比维度 | `<img>` + `srcset` / `sizes` | `<picture>` + `<source>` |
| --- | --- | --- |
| **核心解决场景** | **分辨率切换（Resolution Switching）**：同一张图片，仅在不同尺寸、不同 DPR 间切换以节省带宽 | **美术指导（Art Direction）** 与 **新格式渐进回退（Type Fallback）** |
| **图片内容** | **内容完全相同**，只是分辨率或尺寸不同 | **内容可以裁剪或构图不同**（如移动端展示主体特写，PC 端展示横版大场景） |
| **图片格式探测** | 不支持格式降级探测 | 支持通过 `type="image/avif"` / `type="image/webp"` 优先加载现代高压缩比格式，不支持则回退 JPG |
| **选择决策者** | **浏览器主导**（浏览器可结合设备 DPR、网络状况、省流量模式自主选择最适图片） | **开发者通过媒体查询强制匹配**（符合媒体查询条件即强制选定该源） |

## 你的回答

Image 的 srcset 属性主要是为了让不同 DPR 或宽度的设备中，浏览器能够正确下载最恰当的图片，以优化图片展示效果。

主要有两种设置方式：
1. **利用 DPR**：让浏览器选择对应 DPR 的图片。
2. **根据宽度选择**：让浏览器识别宽度去选择，主要用到图片的真实宽度 `w` 和媒体查询 `sizes` 属性。

具体的决策过程是：
- 浏览器通过视口宽度去查询 `sizes` 属性中写的媒体查询，从而对图片的展示宽度有一个估计；拿到展示宽度之后，还要根据 DPR 做一个换算；然后再去 `srcset` 里面根据宽度去选择。

srcset 和 picture 的 source 的区别在于：后者是做图片格式的兼容。
