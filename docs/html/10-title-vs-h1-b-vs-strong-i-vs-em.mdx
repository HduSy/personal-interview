# 10. title 与 h1、b 与 strong、i 与 em 的区别？

## 1. 三组对比的共同规律：外观相同，语义不同

这三组标签是 HTML 语义化考点的经典三连，观察方式完全一致：**默认渲染效果相同，但语义权重与机器可读性不同**。

- `<b>` 与 `<strong>`：默认都是**粗体**（`font-weight: bold`），差别在「是否表达重要性」。
- `<i>` 与 `<em>`：默认都是**斜体**（`font-style: italic`），差别在「是否表达语气强调」。
- `<title>` 与 `<h1>`：都像是页面的「大标题」，但一个属于**文档元数据**（不在正文里渲染），一个属于**正文章节标题**。

一句话原则：**效果由 CSS 决定，语义由标签名决定**；面试考的从来不是长什么样，而是「这个文本在文档结构里扮演什么角色」。

## 2. `<title>` 与 `<h1>`：元数据标题 vs 内容标题

### 定位差异

| 维度 | `<title>` | `<h1>` |
| --- | --- | --- |
| **所在位置** | `<head>` 内，属于**文档元数据** | `<body>` 内，属于**正文内容** |
| **是否在页面中渲染** | 否（显示在浏览器标签页 / 窗口栏） | 是（页面上最大的标题） |
| **内容限制** | 只能是纯文本，**不能包含任何标签** | 可包含行内元素（`<a>`、`<span>`、`<img>` 等） |
| **数量要求** | 每个文档**必须有且仅有一个** | 规范上允许多个；实际建议每页一个，或每个 `<section>` 一个 |
| **消费方** | 浏览器标签页、书签、历史记录、搜索结果标题、屏幕阅读器 | 页面的章节层级、读屏软件的标题跳转、爬虫的结构识别 |

### 关键差异点

- **`<title>` 是 SEO 里「标题」的真正来源**：搜索结果里那条蓝色可点击的大标题来自 `<title>`，而不是 `<h1>`。`<h1>` 影响的是页面内关键词的权重与结构理解。
- **`<title>` 承担无障碍的「页面名称」**：读屏软件切换标签页时朗读的就是 `<title>`；页面内导航则靠 `<h1>`~`<h6>` 的标题列表。两者分工，不能互相替代。
- **`<title>` 不是「页面上看不到所以不重要」**：恰恰相反，它是唯一横跨标签页、书签、搜索结果的页面标识。
- **工程实践**：`<title>` 通常写成「页面名 - 站点名」，并随路由动态更新（SPA 里很容易被遗漏，是常见的 SEO / a11y 缺陷）；`<h1>` 写页面核心内容标题。

## 3. `<b>` vs `<strong>`，`<i>` vs `<em>`：样式标记 vs 语义标记

### `<b>` 与 `<strong>`

| | `<b>` | `<strong>` |
| --- | --- | --- |
| **语义** | 仅仅让文字在视觉上区隔开，**不表示重要性** | 表示**重要性、严肃性或紧迫性** |
| **适用场景** | 导语中的关键词、产品名、摘要里的关键词，不需要强调语气的场合 | 警告、错误提示、必须注意的关键信息 |
| **默认样式** | 粗体 | 粗体 |
| **机器解读** | 无语义权重 | 部分屏幕阅读器 / 阅读模式会做强调处理，语义上可被识别 |

### `<i>` 与 `<em>`

| | `<i>` | `<em>` |
| --- | --- | --- |
| **语义** | **另一种语态 / 情绪**：术语、外来词、俗语、专有名词、分类学名称 | 表示**语气上的重读、强调**，会改变句子的含义侧重 |
| **适用场景** | 拉丁学名 *Homo sapiens*、外来语、技术术语、人物内心独白 | 「我**没有**说过这句话」这类重音落点 |
| **默认样式** | 斜体 | 斜体 |
| **机器解读** | 无语义权重 | 读屏软件可能读出强调语气；`<em>` **可嵌套**，嵌套表示强调程度加强 |

### 一条判断口诀

> `<strong>` / `<em>` 是「**会改变意思**」的标记——去掉标签，读者会读错重点；
> `<b>` / `<i>` 只是「**换个样式**」的标记——去掉标签，意思完全不变。

举例：

```html
<!-- strong：警告信息，重要性是内容本身的一部分 -->
<p><strong>注意：</strong>该操作不可撤销。</p>

<!-- b：只是视觉上突出扫描关键词，去掉粗体语义不变 -->
<p><b>性能</b>、<b>安全</b>、<b>可维护性</b>是我们最关注的三个方面。</p>

<!-- em：重音位置改变句意 -->
<p>我<em>没有</em>说他偷了钱。</p>

<!-- i：外来语 / 术语，不需要重读 -->
<p>生物学名 <i>Homo sapiens</i> 属于人科。</p>
```

## 4. 补充：实战中的几个高频追问

- **`<b>` 和 `<strong>` 视觉一样，能不能只用 CSS `font-weight` 代替？** 能做出一样的外观，但拿不到语义——SEO、读屏软件、阅读模式无法区分「重要」和「只是加粗」。
- **一页可以有多个 `<h1>` 吗？** HTML5 规范允许（每个 `<section>` 一个），但早期设想的「大纲算法」从未被浏览器和读屏软件真正实现，实践中的建议仍是**一个页面一个 `<h1>`**，用 `<h2>`~`<h6>` 表达层级。
- **`<i>` 现在常被拿来放图标**（Font Awesome 等图标字体）。这是历史遗留的滥用，语义并不正确；现代做法优先用内联 `<svg>`，需要装饰性图标时加 `aria-hidden="true"`。
- **`<em>` 结合 `lang` 属性**：标注外来语时用 `lang` 能让读屏软件用正确语言发音，这比单纯用 `<i>` 更准确。

---

## 你的回答

它们的区别在于语义化与样式。它们在外观上表现都一样，但是 strong、em 以及 h 标签具有语义。

1. **title 与 h1**：
   title 是文档的 meta title（文档元信息），放在 head 标签内，在页面中不渲染展示；而 h1 作为正文的标题，具有语义。

2. **i、b 与 strong、em**：
   i 和 b 在样式上，一个代表斜体，一个代表粗体；而它们分别对应的 strong 和 em，在语义上有强调、重点、严肃等语义规范。

## 口述点评

**评分：6/10**

**总体评价**：开篇一句「区别在于语义化与样式，外观表现一样」把三组对比的共同规律抓住了，这是本题的骨架，方向没错；但骨架之下缺肉——三个具体对比只讲到了「谁在 head、谁渲染」和「谁粗谁斜」这个层次，语义差异本身没有展开。

- **strong 与 em 被合并成一个东西**：这是最大的失分点。两者语义截然不同——`<strong>` 表**重要性 / 严肃性**，`<em>` 表**语气重读**（能改变句意，如「我**没有**说他偷钱」），而且 `<em>` 可嵌套表示强调程度加强。口述里笼统说「强调、重点、严肃」，面试官一追问「那 strong 和 em 什么时候选哪个」就会卡住。
- **`<b>` / `<i>` 说成「只有样式、没有语义」是事实偏差**：按 HTML5 规范它们是有明确语义的——`<b>` 是「引起注意但不表示重要性」（关键词、产品名），`<i>` 是「另一种语态或语气」（术语、外来语、学名）。标准说法是「它们**有**语义，只是不承载重要性/强调」，不是「没有语义」。
- **漏了 title 最高频的追问点**：只说「不渲染、在 head 里」不够。`<title>` 是**搜索结果蓝色大标题的真正来源**，也是读屏软件朗读的「页面名称」，这两条几乎是必追问项；另外「每个文档有且仅有一个 title」这条硬约束也没提。
- **h1 的数量问题没触及**：规范允许多个 h1（每个 section 一个），但大纲算法从未落地，实践建议仍是一页一个——这是三组对比里唯一有争议的点，答出来很加分。另外开篇说「h 标签具有语义」表述略糊，这里比较的对象是 `h1`。
