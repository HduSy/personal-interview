# 12. label 的作用是什么？如何使用？

## 1. 一句话作用

`<label>` 是表单控件的**文字标签**，它把一段可读文本与某个表单控件**绑定**起来，产生两个直接效果：

1. **无障碍**：屏幕阅读器把这个标签文本读作控件的「名字」（accessible name），用户才知道这个输入框是填什么的。
2. **交互**：**点击标签文字等同于点击控件本身**——点「记住我」这四个字就能勾选复选框，点标签能让输入框获得焦点；顺带把可点击热区从一个小方块扩大到整行文字。

本质上，`label` 解决的是「**这个控件叫什么**」的问题：视觉上有文字在旁边，机器和读屏软件却未必知道它俩是一对，`label` 就是这层显式的关联声明。

## 2. 两种关联方式

### (1) 显式关联：`for` + `id`（推荐）

```html
<label for="username">用户名</label>
<input id="username" type="text" name="username">
```

`<label>` 的 `for` 属性值必须与目标控件的 `id` 完全一致。这种写法把「文字」和「控件」解耦，可以用 CSS 自由排布（左右分栏、上下堆叠都行）。

### (2) 隐式关联：把控件包在 `<label>` 内部

```html
<label>
  用户名
  <input type="text" name="username">
</label>
```

只要控件是 `<label>` 的后代元素，就自动与它关联，不需要 `id`。适合「文字紧贴控件」的简单布局。

### 两种方式对比

| 维度 | 显式（`for` / `id`） | 隐式（包裹） |
| --- | --- | --- |
| 是否依赖 `id` | 是，`id` 必须全文档唯一 | 否 |
| 布局灵活性 | 高，文字与控件可任意分栏 | 低，控件必须在标签内部 |
| 可访问性支持 | 最好，工具链识别最稳定 | 良好，但部分老旧辅助技术识别较弱 |
| 适合场景 | 表单主体、复杂布局 | 复选框、单选框等短标签 |

**实践建议：优先用显式关联**，尤其是在组件化 / 服务端渲染的工程里——`for` 与 `id` 的对应关系肉眼可查，也更容易被测试与静态检查工具验证。

## 3. 什么控件可以被 label 关联

只有**可标签元素（labelable elements）**才能被 `label` 关联：

`<button>`、`<input>`（`type="hidden"` 除外）、`<meter>`、`<output>`、`<progress>`、`<select>`、`<textarea>`

对 `<div>`、`<span>`、`<a>` 等非可标签元素写 `for` 是没有效果的。

## 4. 常见坑（面试高频追问点）

### (1) 一个 `label` 里塞了多个控件

```html
<!-- 错误：只有第一个控件会被关联，后面的控件拿不到标签 -->
<label>
  性别
  <input type="radio" name="gender" value="male"> 男
  <input type="radio" name="gender" value="female"> 女
</label>
```

规范上 `<label>` 最多只能包含**一个**可标签后代。单选 / 复选组应当**每个选项各自一个 label**，组名交给 `<fieldset>` + `<legend>`：

```html
<fieldset>
  <legend>性别</legend>
  <label><input type="radio" name="gender" value="male"> 男</label>
  <label><input type="radio" name="gender" value="female"> 女</label>
</fieldset>
```

### (2) 用 `placeholder` 代替 label

`placeholder` 不是标签——它输入后就消失、对比度往往不足、读屏支持不一致，也无法说明字段用途。正确做法是**始终提供 label**，`placeholder` 只作为格式示例（如「请输入 11 位手机号」）。

### (3) `for` 指向不存在的 `id`，或 `id` 重复

`for` 拼错、`id` 重复（同文档出现两次）都会让关联静默失效——不报错，只是点击标签没反应、读屏读不出名字。这是表单里最常见的隐性缺陷。

### (4) 在 `<label>` 里放链接或按钮

`<label>` 的点击会转发给控件，标签内部嵌套 `<a>`、`<button>` 时会与转发行为冲突，触发意外操作。需要链接时把链接放到标签外面。

### (5) 同时写隐式 + 显式，或 `for` 与包裹指向不同控件

两者会叠加成双重标签，读屏可能把名字读两遍；`for` 指向的控件与包裹的控件不一致时行为更是不可预期。**二选一，别混用。**

## 5. 什么时候不用 label

- **控件已有可见文字描述，只想补充程序化名称**：用 `aria-labelledby`（引用现成文本节点的 `id`）或 `aria-label`（直接给字符串）。但注意 `aria-label` 不提供可见文字，能看见的标签优先用 `<label>`。
- **需要给一组控件命名**（单选组、复选组）：用 `<fieldset>` + `<legend>`，而不是 label。
- **纯装饰性图标按钮**：用 `aria-label` 描述功能，如 `<button aria-label="关闭">✕</button>`。

可访问名称的常见计算优先级（简化版）：`aria-labelledby` → `aria-label` → 原生 `<label>` → `title`。所以 `aria-label` 会**覆盖** `<label>` 的文字，排查「读屏读的名字不对」时先查这一点。

## 你的回答

Label 常常跟表单控件绑定在一起，对表单控件进行说明。它主要有两方面的应用场景：

1. **对无障碍友好**：屏幕阅读器可以透过键盘选中 Label，从而告知这个表单项是什么意思。
2. **扩大交互范围**：点击文本即可激活并选中表单控件。

在具体使用上，主要有两种方式：

1. 通过 Label 的 for 属性和表单控件的 ID 属性进行绑定。
2. 将表单控件直接嵌套在 Label 内部。
