# 14. head 标签有什么作用？其中什么标签必不可少？

## 1. head 的作用：文档元信息的容器

`<head>` 是 `<html>` 下的第一个子元素，存放文档的元信息：描述文档是谁、怎么解析、依赖什么资源，不描述页面长什么样。

- 内容不参与页面渲染，唯一例外是 `<title>` 的文本显示在浏览器标签页上。
- 它在浏览器开始渲染之前就被消费：字符编码、视口、渲染模式、样式与脚本都在这一阶段确定，写错的代价高于 body 内容。
- 它是浏览器、爬虫、社交平台和辅助技术读取页面的入口。

它承担五类职责：

| 职责 | 典型元素 |
| --- | --- |
| **解析与渲染的初始条件** | `<meta charset>`（字符编码）、`<meta name="viewport">`（视口） |
| **文档身份与描述** | `<title>`、`<meta name="description">`、`<link rel="canonical">` |
| **资源加载** | `<link rel="stylesheet">`、`<style>`、`<script>`、`<link rel="preload">` / `preconnect` |
| **SEO 与社交分享** | `<meta name="robots">`、Open Graph（`og:*`）、Twitter Card、结构化数据 |
| **平台能力与安全** | `<link rel="manifest">`（PWA）、`<meta name="theme-color">`、`<meta http-equiv>` 类指令 |

## 2. head 里能放什么

只允许 `<title>`、`<base>`、`<link>`、`<style>`、`<script>`、`<noscript>`、`<template>`、`<meta>` 八类。放其他元素（`<div>`、`<p>`、`<img>`）或裸文本都是解析错误，浏览器会隐式结束 `<head>`、开启 `<body>`，把内容挪进 body。

`<head>` 的起止标签在满足条件时可以省略，但其中的元素仍会被解析进隐式 head；实践里一律写全。

## 3. 规范层面：只有 `<title>` 必不可少

`<title>` 是唯一被规范强制要求出现在文档头部的元素，每个文档必须有且仅有一个（例外：`<iframe srcdoc>` 生成的文档，或标题由更高层协议提供时）。它是文档名称，标签页、书签、历史记录、搜索结果和读屏软件朗读的页面名都来自它；没有 title 时这些场景都显示「无标题文档」。与 `<h1>` 的分工见 [10. title 与 h1 的区别](/html/10-title-vs-h1-b-vs-strong-i-vs-em)。

## 4. 工程层面：`charset` 与 `viewport` 事实上必备

规范上两者都有条件（编码已由 HTTP 头声明时，`meta charset` 不是必须），但工程里缺了都会出事：

- **`<meta charset="utf-8">`**：不写要靠浏览器猜编码，猜错就是中文乱码；必须在前 1024 字节内，放后面等于没写。
- **`<meta name="viewport" content="width=device-width, initial-scale=1">`**：不写，移动端按 980px 虚拟视口渲染再整体缩小，媒体查询失准。

面试答法分两层：**规范上只有 `<title>` 必须；实践里 `charset` 和 `viewport` 同样不可省。**

## 5. 一份标准的 head

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <!-- 1. 编码：必须在前 1024 字节内，越靠前越好 -->
  <meta charset="UTF-8">

  <!-- 2. 视口：移动端适配的前提 -->
  <meta name="viewport" content="width=device-width, initial-scale=1">

  <!-- 3. 标题：规范要求的唯一必填项 -->
  <title>面试题库 - 前端学习记录</title>

  <!-- 4. SEO 描述与规范链接 -->
  <meta name="description" content="前端面试题整理与个人复习记录">
  <link rel="canonical" href="https://example.com/html/">

  <!-- 5. 资源预连接 / 预加载 -->
  <link rel="preconnect" href="https://fonts.example.com">
  <link rel="preload" href="/fonts/main.woff2" as="font" type="font/woff2" crossorigin>

  <!-- 6. 样式 -->
  <link rel="stylesheet" href="/assets/main.css">

  <!-- 7. 图标与 PWA -->
  <link rel="icon" href="/favicon.ico">
  <link rel="manifest" href="/manifest.json">
  <meta name="theme-color" content="#ffffff">

  <!-- 8. 社交分享（Open Graph） -->
  <meta property="og:title" content="面试题库">
  <meta property="og:description" content="前端面试题整理与个人复习记录">
  <meta property="og:image" content="https://example.com/og.png">

  <!-- 9. 脚本：无依赖的放 head 并加 defer，或放 body 末尾 -->
  <script src="/assets/main.js" defer></script>
</head>
<body>
  ...
</body>
</html>
```

顺序要求：`charset` 最优先（1024 字节限制），`viewport` 紧随其后；`title` 与 `description` 尽量靠前；样式表在脚本之前，避免脚本执行时还要等样式。

## 6. 常见坑

- **`<meta charset>` 写在 1024 字节后**：等于没声明；长注释、过长标题、前置脚本都可能把它挤出去。
- **`viewport` 用 `user-scalable=no`**：禁用用户缩放，属无障碍问题，现代浏览器已开始忽略。
- **head 里塞 `<div>` 等元素**：解析器提前结束 head，内容被挪进 body。
- **title 为空或全站相同**：SPA 路由不更新，书签和搜索结果同名。
- **`<base>` 写错**：影响所有相对 URL，只允许出现一个，可能让整站资源 404。
- **`<style>` 放 head 最底部且前面有同步脚本**：脚本阻塞解析，首屏白屏变长。

## 7. 资源加载

- **CSS 放 head，JS 放 body 末尾或 head 加 `defer` / `async`**：CSS 放 head 是为了尽早下载、避免无样式闪烁，渲染会等待 CSSOM；脚本会阻塞 HTML 解析，放末尾或用 `defer` / `async` 不阻塞首屏（详见 [04. defer 与 async](/html/04-script-defer-vs-async)）。
- **预加载指令**：`preload` 提前加载当前页马上要用的资源（必须写 `as`，否则只是低优先级抓取）；`prefetch` 预取下一页可能用到的资源；`preconnect` 提前完成 DNS + TCP + TLS 握手；`dns-prefetch` 只提前做 DNS 解析。

## 8. 其他边界

- **CSP 可以写在 meta 里**，但 `frame-ancestors`、`report-uri`、`sandbox` 等指令在 meta 中无效，生产仍以 HTTP 响应头为主。
- **`<noscript>` 在 head 里只能放** `<link>`、`<style>`、`<meta>`。
- **SEO**：`title`、`description`、`canonical`、`robots` 和结构化数据直接影响搜索结果；`<h1>` 影响内容权重，两者分工不同。

## 你的回答

Head 是存放文档源信息的一个容器，里面常用来放文档的源信息，用户不会看到，因为它不像在页面里面。

1. **常用标签与配置**：
   Head 里面支持放得最多的就是 title 和 meta 标签。meta 常配置的源信息有：
   (a) charset="utf-8"：设置页面解析的字符编码。
   (b) 通过 name 属性配置 meta description、meta keywords，或者是 viewport 做移动端的适配。

2. **依赖资源与加载策略**：
   另外，Head 也会放一些文档所依赖的资源，比如 link 引用外部 CSS、style 内联写 CSS，或者 script 等等。
   (a) CSS 的加载：style 常常放在 Head 里面，是为了避免页面无样式闪烁，让 CSS 尽快地加载并构建完整的 CSSOM 对象。
   (b) JS 的加载：JS 常常放在 body 的最最最尾部，或者通过 defer 属性放在 Head 标签里。这是为了避免 JS 的加载、解析、执行去阻塞页面的渲染，造成页面白屏。

**总体评价**：第一问答得漂亮——「元信息的容器 + 用户看不见 + CSS 避免 FOUC 并构建 CSSOM + 脚本阻塞解析所以用 defer 或放尾部」，这四句都是机制级的准确表述，不是背概念。但题干第二问「**其中什么标签必不可少**」整段没有回答，这是本题失分的主因（另：口述里的「源信息」应为「元信息 / metadata」）。

- **「必不可少的标签」完全没答**：这是题干的第二个问号，也是这道题真正的区分点。必须分层作答——**规范层面只有 `<title>` 是强制要求的**（每个文档有且仅有一个，它是文档名称、标签页与搜索结果标题的来源）；**工程层面 `<meta charset>` 与 `<meta name="viewport">` 事实上不可省**。只答第一层会被追问「meta 都必要吗」，只答第二层会漏掉规范硬约束。
- **charset 和 viewport 只讲了「是什么」，没讲「不写会怎样」**：`charset` 必须出现在文档**前 1024 字节内**，放晚了等于没声明，浏览器只能猜编码，猜错就是中文乱码；`viewport` 不写时移动端会按 **980px 虚拟视口**渲染再整体缩小，页面像被压扁的桌面版，媒体查询全部失准。这两句后果一补，说服力完全不同。
- **`meta keywords` 不该当常用配置讲**：主流搜索引擎早已不再使用它（Google 从未把它当排名因素，Bing 甚至视其为垃圾信号），把它和 description、viewport 并列会显得资料偏旧。SEO 侧现在更重要是 `description`、`canonical`、`robots` 和 Open Graph。
- **可以再补一层边界**：head 允许的子元素只有 `title`、`base`、`link`、`style`、`script`、`noscript`、`template`、`meta` 这八类；放 `<div>` 之类的元素会被解析器当作 head 结束，内容自动挪进 body——这是「为什么我写在 head 里的东西跑到 body 了」的答案，很实用。
