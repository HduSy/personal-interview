# 15. 渐进增强和优雅降级之间的区别？

## 1. 一句话区分：构建顺序相反

渐进增强（Progressive Enhancement，PE）先构建兼容性最好的基础版本（语义化 HTML，内容可读、核心功能可用），再针对能力更强的环境逐层叠加样式、交互和现代 API。优雅降级（Graceful Degradation，GD）先针对能力最强的新环境做出完整实现，再向下兼容，让能力不足的环境退化而不崩溃。PE 自下而上增强，GD 自上而下回退。

## 3. 全面对比

| 维度 | 渐进增强 | 优雅降级 |
| --- | --- | --- |
| **构建起点** | 最底层、兼容性最好的环境 | 最高层、能力最新的环境 |
| **方向** | 自下而上，逐层叠加 | 自上而下，逐层兜底 |
| **默认假设** | 「假设环境很差，先保证能用」 | 「假设环境很好，先做完整」 |
| **核心关注** | 内容与核心功能**永远可用** | 完整**体验**，并为旧环境补兼容 |
| **代码形态** | 分层：HTML 打底 → CSS 增强 → JS 增强 | 主逻辑完整，外加环境检测与回退分支 |
| **无障碍 / SEO** | 天然友好（语义化 HTML 是地基） | 容易被忽略（内容常藏在 JS 之后） |
| **开发成本** | 前期架构成本高，后期维护稳定 | 前期快，降级分支常是事后补丁，容易漏 |
| **失败模式** | 最差情况是「朴素但能用」 | 最差情况是「好看但用不了 / 直接白屏」 |
| **典型代表** | MPA / SSR、Astro 岛屿架构、PWA | 早期 SPA、依赖新 CSS 特性的营销页 |

## 4. 具体场景对照

### (1) 表单校验

```html
<!-- 渐进增强：HTML 原生约束是地基，JS 只是即时反馈的增强 -->
<form action="/submit" method="post">
  <label for="email">邮箱</label>
  <input id="email" name="email" type="email" required>
  <button type="submit">提交</button>
</form>
```

PE 写法：服务端和 HTML 原生约束保证一定能校验，JS 只负责即时提示、无刷新提交。JS 失效时表单仍能提交并被校验。

GD 写法：先写完整的 JS 校验逻辑，再补无 JS 场景；这一层常被遗漏，结果是 JS 挂了可以提交任意脏数据。

### (2) CSS 新特性

两者使用同一套特性检测工具（`@supports`），差别在默认值怎么设：

```css
/* 渐进增强：默认就是能用的简单布局，支持时才升级 */
.card { display: block; }

@supports (display: grid) {
  .grid { display: grid; gap: 16px; }
}

/* 优雅降级：默认用新特性，不支持时才回退 */
.grid { display: grid; gap: 16px; }

@supports not (display: grid) {
  .grid { display: flex; flex-wrap: wrap; }
  .grid > * { width: 33.333%; }
}
```

PE 默认就是能用的简单布局，支持时才升级；GD 默认使用新特性，不支持时才回退。两者功能等价，但 PE 不需要给老环境写基础样式，GD 必须记得补回退分支。

### (3) 链接与交互

PE：`<a href="/detail/1">` 本身可跳转，JS 接管后变成无刷新浮层；JS 不可用时退化为普通跳转，功能不丢。

GD：用 `<div onclick="open()">` 实现浮层，再给无 JS 环境补 `<noscript>` 提示或链接，补不补取决于实现者。

## 5. 现代工程里的体现

现代工程普遍以 PE 作为架构原则：

- **SSR / MPA**：先返回可读的 HTML，再水合（hydrate）加交互；纯 CSR 的 SPA 更接近 GD。
- **岛屿架构（如 Astro）**：默认零 JS，只为需要交互的岛屿加载脚本，是 PE 的极端形式。
- **PWA**：基础网页可访问，Service Worker 叠加离线能力，再叠加推送、安装。
- **特性检测而非浏览器嗅探**：`if ('serviceWorker' in navigator)`、`@supports`，直接检测能力而非猜测环境。
- **CSS 忽略未知属性**：解析器遇到不认识的属性会直接忽略并继续解析后续声明，天然支持新样式增强、老浏览器忽略。

## 6. 面试怎么答与常见误区

按「一句话定义 → 构建方向相反 → 一个 CSS 或表单例子 → 现代工程体现 → 判断」展开。

收尾判断：两者不是互斥的技术，而是两种默认值设定——PE 把默认值设在最差环境，GD 设在最好环境。现代工程通常以 PE 为架构原则，保证基础可用、可访问、SEO 友好；在具体增强层用 GD 的思路回退。

常见误区：

- PE 不是单纯给老浏览器做兼容，而是让内容和核心功能不依赖 CSS/JS 的架构原则。
- GD 没有过时，只是变成「特性检测 + 回退」的形式。
- 两者不必二选一，实践中 PE 为主、GD 为辅。
- PE 前期有架构成本，但换来无障碍、SEO、鲁棒性和可维护性。
