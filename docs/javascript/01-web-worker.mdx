# 01. 对 Web Worker 的理解

## 1. 需要 Web Worker 的原因

JavaScript 是单线程的，浏览器中 JS 引擎线程与 GUI 渲染线程互斥。主线程执行高耗时计算（大型算法、大文件切片哈希、海量数据清洗、图像/视频滤镜）时，事件循环被阻塞，页面无法响应点击、滚动，也无法按时完成每帧 16.6ms 的重绘，导致卡顿、无响应甚至假死。Web Worker 允许在主线程之外创建独立后台线程并行执行耗时任务，主线程专注 UI 渲染和用户交互。

## 2. 通信机制与数据传递

主线程与 Worker 内存隔离，不能直接共享同一变量，只能通过消息传递通信：发送方 `postMessage(data)`，接收方监听 `onmessage`。三种传递方式：

1. **结构化克隆**：默认方式，深拷贝数据，两端各持有一份互不影响的数据；传递几百 MB 的大对象会有序列化和反序列化开销。
2. **可转移对象**：针对 `ArrayBuffer`、`MessagePort`、`ImageBitmap` 等大二进制数据，零拷贝转移内存所有权，原线程数据变为 0 字节，耗时几乎为 0。
3. **共享内存**：`SharedArrayBuffer` + `Atomics`，多线程共享同一块内存，`Atomics` 原子操作避免数据竞态。受 Spectre 漏洞影响，现代浏览器需在服务端配置 COOP 和 COEP 响应头才能启用。

## 3. 运行环境与安全沙箱限制

Worker 运行在 `DedicatedWorkerGlobalScope` 中，顶层对象是 `self` 而非 `window`，并受以下限制：

| 权限维度 | Worker 内部状态 | 具体说明 |
| --- | --- | --- |
| **DOM 访问** | **严禁访问** | 无法访问 `document`、`window`、无法操作任何 DOM 节点（彻底杜绝多线程竞争修改 DOM 的并发死锁） |
| **BOM 访问** | **部分受限** | 无法访问 `window.parent`、`alert`、`confirm`；但**允许访问**只读的 `navigator`（判断设备环境）和 `location`（仅 Worker 自身脚本 URL） |
| **异步与网络通信** | **完全支持** | 允许使用 `fetch`、`XMLHttpRequest`、`WebSocket`、`setTimeout`、`setInterval` |
| **模块与外部脚本加载** | **完全支持** | 允许使用 `importScripts('utils.js')` 同步加载外部脚本，现代浏览器支持原生 ES 模块（`new Worker('w.js', { type: 'module' })`） |
| **同源策略限制** | **严格同源** | Worker 脚本文件的 URL 必须与主页面同源（本地测试不能用 `file://` 协议，跨域脚本需通过 Blob URL 转换绕过） |
| **系统资源消耗** | **需手动销毁** | 每个 Worker 对应一个真实的操作系统线程，大量创建会迅速耗尽 CPU 和内存。使用完毕必须在主线程调用 `worker.terminate()` 或在内部调用 `self.close()` 主动释放 |

## 4. Worker 类型与应用场景

Web Worker 分为三种：

1. **Dedicated Worker（专用 Worker）**：仅归属于创建它的单个页面，页面关闭即销毁，最常用。
2. **Shared Worker（共享 Worker）**：同源下多个标签页、iframe 可共同连接，用于多标签页数据同步、跨页面 WebSocket 单连接复用。
3. **Service Worker（服务工作线程）**：常驻后台代理浏览器与网络之间的请求，用于拦截请求、离线缓存（PWA）和后台推送。

典型场景：

1. **超大文件分片与哈希**：几 GB 视频上传前的前端切片，以及用 SparkMD5 计算文件完整性哈希。
2. **前端海量数据导出与报表解析**：直接解析几十万行的 Excel/CSV 并做多维排序筛选。
3. **Canvas 图像与音视频滤镜**：结合 `OffscreenCanvas`，把 WebGL/2D 渲染放到 Worker 后台线程。
4. **语法高亮与代码格式化**：Monaco Editor 的语法解析器放在 Web Worker 中异步处理。

## 5. 最小化代码模板

```javascript
// main.js (主线程)
const worker = new Worker('./worker.js');

// 1. 向 Worker 发送任务
worker.postMessage({ type: 'CALC', payload: 10000000 });

// 2. 接收 Worker 返回的结果
worker.onmessage = function (e) {
  console.log('主线程收到计算结果:', e.data.result);
  // 3. 任务彻底结束，及时销毁 Worker 释放系统资源
  worker.terminate();
};

worker.onerror = function (err) {
  console.error('Worker 发生异常:', err.message);
};
```

```javascript
// worker.js (Worker 独立线程)
self.onmessage = function (e) {
  const { type, payload } = e.data;
  if (type === 'CALC') {
    // 模拟密集型 CPU 计算
    let total = 0;
    for (let i = 0; i < payload; i++) {
      total += i;
    }
    // 将计算结果回传给主线程
    self.postMessage({ result: total });
  }
};
```
