# 03. 词法作用域和动态作用域是什么？有什么区别？

## 高频问答

### 1. 面试官：词法作用域和动态作用域是什么？有什么区别？

**回答**：区别在一句话里——**词法作用域由「写代码的位置」决定，动态作用域由「调用时的调用栈」决定**。词法作用域下，函数能访问哪些变量在**函数定义时**就定了，写在哪层就嵌套在哪层；动态作用域下，要**调用时**从调用者开始沿调用链往外找。**JavaScript 是词法作用域**——这是必须先说的结论；动态作用域的现役代表是 Bash 和 Emacs Lisp。

最小对比例子：

```js
let x = '全局';

function foo() {
  console.log(x);
}

function bar() {
  let x = 'bar 内部';
  foo();
}

bar();
```

`foo` 里没有 `x`，往哪找？词法作用域**看定义处**：`foo` 定义在全局，沿「foo → 全局」找到 `'全局'`；动态作用域**看调用处**：`foo` 被 `bar` 调用，沿「foo → bar → 全局」先在 `bar` 里找到 `'bar 内部'`。同一份代码，两种模型输出不同——这就是全部区别。可以现场验证：

### 2. 面试官：词法作用域的机制是什么？为什么和调用位置无关？

**回答**：**函数创建时把定义时的词法环境存进内部引用（`[[Environment]]`），每次调用新环境的外层指针指向它，而不是指向调用者**。这根指针决定了「在哪定义」永远压过「在哪调用」。它直接派生两个核心概念：**闭包**（函数携带定义时的词法环境，外层返回后环境仍在）和**变量遮蔽**（内层同名变量遮住外层，沿链就近命中）。

### 3. 面试官：this 是不是就是动态作用域？

**回答**：不是，只是行为像。`this` 在**调用时**绑定（谁调用指向谁），看上去和动态作用域一样「由调用决定」；但它**不是作用域链上的标识符**，是执行上下文里的独立绑定，遵循四条调用规则。最有力的佐证：**箭头函数没有自己的 this，沿词法作用域链取外层的**——把 this 变成了词法绑定，说明两者本来就是两套机制。

### 4. 面试官：为什么 JavaScript 不设计成动态作用域？

**回答**：词法作用域**静态可分析**——变量关系在解析期就能确定，引擎才能做变量地址预计算，打包器才能 tree-shaking，lint 才能查未使用变量；动态作用域必须运行到那一步才知道绑定关系，这一整条工具链都不成立，代码可预测性也差。

### 5. 面试官：eval 和 with 是怎么回事？

**回答**：它们是历史遗留的「欺骗词法作用域」手段——`eval` 在运行时注入声明，`with` 把对象变成一个作用域。代价是引擎对该函数放弃静态优化，所以严格模式**禁用 `with`**、`eval` 内的声明不再泄漏到外层。

## 加深理解

### 调用栈和环境链为什么是两棵不同的树

执行时有两套结构：**调用栈**（函数谁调用谁，动态）和**环境链**（作用域谁套谁，静态）。词法作用域的含义就是「环境链在函数定义时已经画好，与调用栈无关」。动态作用域语言里查找沿调用栈走，环境关系退化为调用关系的影子——`bar()` 里调 `foo()` 的输出取决于整条调用路径，同一个函数在不同上下文调用结果不同，这就是它难以静态分析的原因。

### `return f()` 和 `return f` 的经典两段代码差在哪

```js
function checkscope() {
  var scope = 'local scope';
  function f() { return scope; }
  return f;          // 对比：return f();
}
checkscope()();      // 'local scope'
```

两段代码都输出 `local scope`——`f` 定义在 `checkscope` 里，`scope` 的绑定在定义时已确定（词法作用域）。差异在执行过程与内存：

1. **`return f()`**：`f` 在 `checkscope` 内部被调用，此刻 `checkscope` 的执行上下文还在调用栈上，沿栈上活着的上下文链查找——普通嵌套调用；
2. **`return f`**：`f` 被带到全局调用时，`checkscope` 早已出栈、栈帧已销毁——仍能取到 `scope`，靠的是闭包：`f` 创建时的 `[[Environment]]` 持有 `checkscope` 的词法环境，栈帧没了，环境对象因被引用留在堆上；
3. 因此第二段里 `scope` 的生命周期被 `f` 拉长，`f` 可达它就不能被回收。

第二段代码的调用栈上根本没有 `checkscope`，查找照样命中——「环境链与调用栈是两棵树」的具体实证。

### this 四条规则的优先级

默认绑定 < 隐式绑定（obj.fn()）< 显式绑定（call/apply/bind）< new 绑定。箭头函数不进这套规则：它没有 this，取**定义时**外层作用域的 this，且 bind 也改不动。所以严格说「箭头函数的 this 是词法的」这句常见说法是对的——代价是它连 new 都不能用。

### ESM 为什么设计成静态结构

`import/export` 必须写在顶层、名字必须是字符串字面量、绑定关系解析期确定——这些限制就是在强制词法作用域式的静态性，使 tree-shaking、循环依赖处理、顶层提升成为可能；CommonJS 的 `require` 是运行时函数调用，可以在任何位置条件执行，因此只能做运行时分析。作用域模型的选择直接决定了模块体系的工具链形态。
