# 03. 词法作用域和动态作用域是什么？有什么区别？

## 高频问答

### 1. 一句话分清两种模型

作用域是「一个标识符（变量名、函数名）指向哪里」的解析规则。两种模型：

- **词法作用域（lexical / static scope）**：函数能访问哪些变量，在**函数定义时**由代码书写位置决定——写在哪层，就嵌套在哪层；
- **动态作用域（dynamic scope）**：函数能访问哪些变量，在**函数调用时**由**调用栈**决定——从调用者开始沿调用链往外找。

**JavaScript 是词法作用域**——这是必须先说的结论。动态作用域的现役代表是 Bash 与 Emacs Lisp。

### 2. 最小对比例子

```js
let x = '全局';

function foo() {
  console.log(x);
}

function bar() {
  let x = 'bar 内部';
  foo();
}

bar();
```

`foo` 里没有 `x`，往哪找？**词法作用域看定义处**：`foo` 定义在全局，沿「foo → 全局」找到 `'全局'`；**动态作用域看调用处**：`foo` 被 `bar` 调用，沿「foo → bar → 全局」先在 `bar` 里找到 `'bar 内部'`。同一份代码，两种模型输出不同——这就是全部区别。

### 3. 机制：函数创建时保存的那个环境

词法作用域的实现：**函数创建时把定义时的词法环境存进内部引用（`[[Environment]]`），每次调用新环境的外层指针指向它**——而不是指向调用者的环境。这根指针决定了「在哪定义」永远压过「在哪调用」。

它直接派生出两个前端核心概念：

- **闭包**：函数携带其定义时的词法环境——内层函数在定义处「记住」外层变量，哪怕外层已经返回；
- **变量遮蔽**：内层同名变量遮住外层，查找沿词法链就近命中。

### 4. `this` 像「动态作用域」但不是

`this` 的绑定时机在**调用时**（谁调用指向谁），行为上「像」动态作用域，面试常被追问。准确的说法：`this` **不是作用域链上的标识符**，是执行上下文里的绑定，遵循四条调用规则（默认 / 隐式 / 显式 / new）；变量查找是词法的，`this` 绑定是「动态的」，两者并行不悖。

佐证：**箭头函数没有自己的 `this`，沿词法作用域链取外层的**——恰恰是把 `this` 变成了词法绑定，也说明二者本是两套机制。

**为什么 JS 不设计成动态作用域？** 词法作用域静态可分析：变量关系在解析期确定，引擎才能做变量地址预计算，打包器才能做 tree-shaking、lint 才能查未使用变量；动态作用域必须运行到那一步才知道绑定关系，一切静态工具链失效，代码可预测性也差。

**eval / with 是怎么回事？** 它们是历史遗留的「欺骗词法作用域」手段：`eval` 在运行时注入声明、`with` 把对象变成一个作用域。代价是引擎对该函数放弃静态优化，所以严格模式**禁用 `with`**、`eval` 内的声明不再泄漏到外层。

## 加深理解

### 调用栈和环境链为什么是两棵不同的树

执行时有两套结构：**调用栈**（函数谁调用谁，动态）和**环境链**（作用域谁套谁，静态）。词法作用域的含义就是「环境链在函数定义时已经画好，与调用栈无关」。动态作用域语言里查找沿调用栈走，环境关系退化为调用关系的影子——`bar()` 里调 `foo()` 的输出取决于整条调用路径，同一个函数在不同上下文调用结果不同，这就是它难以静态分析的原因。

### `return f()` 和 `return f` 的经典两段代码差在哪

```js
function checkscope() {
  var scope = 'local scope';
  function f() { return scope; }
  return f;          // 对比：return f();
}
checkscope()();      // 'local scope'
```

两段代码都输出 `local scope`——`f` 定义在 `checkscope` 里，`scope` 的绑定在定义时已确定（词法作用域）。差异在执行过程与内存：

1. **`return f()`**：`f` 在 `checkscope` 内部被调用，此刻 `checkscope` 的执行上下文还在调用栈上，沿栈上活着的上下文链查找——普通嵌套调用；
2. **`return f`**：`f` 被带到全局调用时，`checkscope` 早已出栈、栈帧已销毁——仍能取到 `scope`，靠的是闭包：`f` 创建时的 `[[Environment]]` 持有 `checkscope` 的词法环境，栈帧没了，环境对象因被引用留在堆上；
3. 因此第二段里 `scope` 的生命周期被 `f` 拉长，`f` 可达它就不能被回收。

第二段代码的调用栈上根本没有 `checkscope`，查找照样命中——「环境链与调用栈是两棵树」的具体实证。

### this 四条规则的优先级

默认绑定 < 隐式绑定（obj.fn()）< 显式绑定（call/apply/bind）< new 绑定。箭头函数不进这套规则：它没有 this，取**定义时**外层作用域的 this，且 bind 也改不动。所以严格说「箭头函数的 this 是词法的」这句常见说法是对的——代价是它连 new 都不能用。

### ESM 为什么设计成静态结构

`import/export` 必须写在顶层、名字必须是字符串字面量、绑定关系解析期确定——这些限制就是在强制词法作用域式的静态性，使 tree-shaking、循环依赖处理、顶层提升成为可能；CommonJS 的 `require` 是运行时函数调用，可以在任何位置条件执行，因此只能做运行时分析。作用域模型的选择直接决定了模块体系的工具链形态。
