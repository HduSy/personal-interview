# 04. 谈谈 JavaScript 的执行上下文栈

## 高频问答

### 1. 是什么：管理「谁在执行」的调用栈

JS 是单线程，同一时刻只能执行一个函数。引擎为**每次函数调用**创建一个**执行上下文**（execution context）——里面装着这次调用需要的变量环境、外部引用、`this` 绑定——并把上下文压入**执行上下文栈**（即调用栈）管理：

- 栈底是**全局执行上下文**，程序启动即入栈，页面卸载才出栈；
- 调用函数 → 新上下文入栈并开始执行；函数返回 → 其上下文出栈，控制权交还上一层；
- 后进先出，**正在执行的永远在栈顶**。

栈溢出就是它：递归没有出口把栈压满，抛 `RangeError: Maximum call stack size exceeded`。

### 2. 执行上下文的三种

| 类型 | 数量 | 说明 |
| --- | --- | --- |
| 全局执行上下文 | 程序唯一 | 栈底，浏览器对应全局 `window` |
| 函数执行上下文 | 每次调用一个 | 同一函数多次调用，上下文各自独立 |
| `eval` 执行上下文 | 每次 eval 一个 | 性能差、严格模式受限，了解即可 |

「同一函数多次调用上下文独立」是递归能工作的前提——每层递归各有自己的参数和局部变量，互不覆盖。

### 3. 上下文里有什么：两套规范说法

经典教程（ES3 时代）的说法：上下文包含**变量对象（VO / 活动对象 AO）、作用域链、this**。ES6 起规范改写为两个环境 + this：

- **变量环境（VariableEnvironment）**：登记 `var` 与函数声明——**提升时初始化为 `undefined` / 整体提升**；
- **词法环境（LexicalEnvironment）**：登记 `let / const`——**提升但不初始化**，声明语句执行前访问抛 `ReferenceError`，即**暂时性死区（TDZ）**；
- **`this` 绑定**与**外部环境引用（outer）**：`outer` 来自函数定义时的 `[[Environment]]`——这正是词法作用域的机制（词法作用域题里详细讲过）。

面试答哪套都对，能说清「两套是新旧规范的演进关系」是加分项。

### 4. 一次调用的完整生命周期

以 `a() → b() → c()` 为例：

```text
栈变化：全局 → a → b → c
c 返回：全局 → a → b
b 返回：全局 → a
a 返回：全局
```

每个上下文两个阶段：**创建阶段**（登记变量与函数声明、确定 `this` 与 `outer`）→ **执行阶段**（逐行赋值、执行）。变量提升的全部真相就是「创建阶段的登记发生在执行阶段之前」。

### 5. 与作用域链的分工（高频追问）

**执行上下文栈管「谁在执行」（动态），作用域链管「变量去哪找」（静态）**——两棵树，词法作用域题里详细对比过。落点：

- 函数在哪里被调用不影响它查变量（查环境链）；调用只决定上下文何时入栈出栈（执行栈）；
- **上下文出栈 ≠ 环境销毁**：闭包函数被外部持有时，栈帧没了、它定义时的词法环境仍在堆上被引用（`return f` 那个经典例子讲的就是这个）。

**异步回调进不进这个栈？** 不进。定时器、Promise 回调先进任务队列，**当前执行栈清空后**才由事件循环取出执行——每个回调执行时同样会短暂压栈出栈。

## 加深理解

### 为什么每个函数调用要独立上下文

如果没有独立的上下文，递归的第二层就会覆盖第一层的 `n` 和局部变量，无法回溯。独立上下文配合栈的 LIFO，天然实现「逐层进入、逆序返回」——递归、函数嵌套、异常冒泡都建立在这个结构上。代价是栈容量有限（浏览器通常万级），深递归要么改循环要么改尾递归优化（Safari 之外基本没实现，不可依赖）。

### VO / AO 与词法环境是什么关系

ES3 规范用变量对象（VO）描述变量的存储，函数调用时称活动对象（AO）；ES6 规范重写执行模型，拆成词法环境与变量环境，`let/const` 与 `var` 的不同提升行为从此有了正式位置（声明式环境记录 vs var 环境记录）。两套说法描述的是同一件事的不同时代建模，读老资料用 VO/AO 对照即可。

### Error().stack 为什么能拍到调用栈

Error 对象构造时会捕获**当时的执行栈快照**存入 stack 字符串——这是观察执行栈最直接的手段，也是 console.trace 的实现基础。注意快照是构造那一刻的：想在函数入口看栈就在入口 new Error，出栈后再看同一对象仍是旧快照。

### 全局上下文为什么永远在栈底

页面一启动全局代码就开始执行，此后所有函数调用都是它的子孙节点；只要页面不卸载，全局上下文就持有所有全局变量与函数声明。也因此全局上下文从不「返回」——浏览器关闭页面才销毁它，栈空即程序结束。
