# 05. 作用域链是什么？

## 高频问答

### 1. 定义：标识符查找的路径

作用域链是**查找变量（标识符）时依次经过的作用域连成的路径**：当前作用域 → 外层作用域 → 再外层 → 全局作用域，逐环境找，第一个命中即停；到全局仍未命中抛 `ReferenceError`。

关键在确定时机：**函数定义时，链上除自己以外的部分就已确定**（词法作用域，定义在哪层就链到哪层）；函数调用只是在链的最前端插入本次调用的环境。所以「函数的作用域链在定义时创建」这句经典表述是对的——执行上下文题里 [[Scope]] / `[[Environment]]` 讲的就是它的实现。

### 2. 查找规则三条

1. **就近遮蔽**：从链头向外逐环境找，内层同名标识符遮住外层，命中即停，不再往外；
2. **查不到报错**：到全局环境仍没有 → `ReferenceError`（引用未声明变量）；
3. **赋值也要先沿链找**：找到目标就赋值；整条链都没有时，非严格模式隐式创建全局变量，严格模式抛 `ReferenceError`——「不声明直接赋值」的危险就在这。

### 3. 链的长短由什么决定

- **嵌套函数**每定义一层，链加一节；
- **块级作用域**：`let / const` 的每个块（`if`、`for` 的 `{}`）都是一个独立环境，块内声明的标识符是链上的一节；`for (let i ...)` 更特殊——**每轮迭代创建新环境**，所以循环里的异步回调各自拿到 0、1、2，而 `var` 只有一个函数级环境，回调拿到的全是 3；
- **历史上 with / catch 能「延长作用域链」**（把对象插到链前端，属性当变量查）——现代严格模式**禁用 with**，`catch (e)` 的 `e` 只是块级作用域变量，「延长作用域链」的说法已成历史，面试提到要能对上号。

### 4. 与原型链的区别（高频对比）

| | 作用域链 | 原型链 |
| --- | --- | --- |
| 查找什么 | 标识符（变量名、函数名） | 对象的属性 |
| 沿着什么 | 词法环境的 `outer` 引用 | 对象的 `[[Prototype]]` |
| 何时确定 | 函数定义时（词法） | 对象创建 / 原型连接时 |
| 未命中的结局 | `ReferenceError` | `undefined`（不报错） |

两条链会叠加工作：`obj.a` 先沿作用域链找到 `obj` 这个标识符，再沿 `obj` 的原型链找属性 `a`。原型与原型链题里详细讲过第二条链。

**「局部变量比全局变量访问快」还对吗？** 老依据就是链深度——局部在链头、全局在链尾。现代引擎有内联缓存和环境的形状优化，命中访问都接近一次指针解引用，**实测差距可忽略**；把它当知识点答可以，当优化手段写代码没必要（原型链那题讲过同样的结论）。

**IIFE 当年为什么流行？** 在没有块级作用域和模块的年代，用「函数作用域」把私有变量包起来、只暴露少量接口，避免标识符堆到全局环境（链的最后一节、所有代码共享）。`let / const` + ESM 出来后，这个用途消失了。

## 加深理解

### ES3 的 [[Scope]] 和 ES6 的 [[Environment]] 是一回事吗

指同一机制的两代建模：ES3 说函数创建时把父级变量对象链存进内部属性 [[Scope]]，调用时创建自己的 AO 放到链前端；ES6 说函数创建时保存定义时的词法环境到 [[Environment]]，调用时新环境的 outer 指向它。表述不同，结论一致——**链的外层部分在定义时冻结，调用只补最前面一节**。这也是「改变函数定义位置就改变它的作用域链」的原因。

### for 循环的 let 到底创建了几个环境

每轮迭代一个，共 N + 1 个（外加循环体外的那个块环境登记 i 的初值更新）。每轮环境里保存当轮的 i，异步回调闭包引用的是「自己那轮」的环境，所以输出 0、1、2。var 只有一个函数级环境，N 个回调共享同一个 j，回调执行时循环早已结束，j 已是 3。这是「作用域链 + 闭包」交叉出题率最高的一个场景。

### 为什么 with 被禁用

`with (obj) { ... }` 把 obj 插到作用域链最前端，块内的每个标识符都可能是 obj 的属性——引擎无法在解析期确定标识符绑定到哪一节，只能关闭该函数的静态优化。且「属性当变量」让代码语义含混（obj 上有没有这个属性决定了行为）。严格模式直接语法报错，`catch (e)` 的历史待遇也被块级作用域收编。
