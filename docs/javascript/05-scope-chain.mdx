# 05. 作用域链是什么？

## 高频问答

### 1. 面试官：作用域链是什么？

**回答**：作用域链是**查找变量时依次经过的作用域连成的路径**：当前作用域 → 外层作用域 → 再外层 → 全局作用域，逐环境找，第一个命中即停，到全局仍未命中抛 `ReferenceError`。关键在确定时机：**函数定义时，链上除自己以外的部分就已确定**；函数调用只是在链的最前端插入本次调用的环境——所以「函数的作用域链在定义时创建」这句经典表述是对的，机制在[执行上下文题](/javascript/04-execution-context-stack)的 `[[Scope]]` / `[[Environment]]` 里。

### 2. 面试官：查找和赋值分别怎么走这条链？

**回答**：三条规则。**读取就近遮蔽**：从链头向外逐环境找，内层同名标识符遮住外层，命中即停；**查不到报错**：到全局环境仍没有，抛 `ReferenceError`；**赋值也要先沿链找**：找到目标就赋值，整条链都没有时，非严格模式隐式创建全局变量，严格模式抛 `ReferenceError`——「不声明直接赋值」的危险就在这。

### 3. 面试官：for 循环里用 let 和 var，异步回调的输出为什么不同？

**回答**：`for (let i ...)` **每轮迭代创建一个新环境**，每个异步回调闭包引用的是「自己那轮」的 `i`，输出 0、1、2；`var` 只有一个函数级环境，N 个回调共享同一个 `i`，回调执行时循环早已结束，输出全是 3。这也是「作用域链 + 闭包」交叉出题率最高的场景，现场验证：

<Sandpack
  template="static"
  showConsole
  height={200}
  html={`<p style="font-family: system-ui; padding: 12px; color: #666; font-size: 13px;">
  打开下方 Console 查看验证输出
</p>`}
  js={`let x = '全局';

function outer() {
  let x = 'outer 层';
  function inner() {
    let x = 'inner 层';
    console.log('① 就近遮蔽：', x);
  }
  inner();
}
outer();

function outer2() {
  let y = 'outer2 的 y';
  function inner2() { console.log('② 沿链向外：', y); }
  inner2();
}
outer2();

try { console.log(notExist); } catch (e) {
  console.log('③ 查不到：', e.name);
}

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log('let:', i), 0);
}
for (var j = 0; j < 3; j++) {
  setTimeout(() => console.log('var:', j), 0);
}`}
/>

顺带两个边界：`let / const` 的每个块（`if`、`for` 的 `{}`）都是独立环境，块内声明是链上的一节；历史上 `with` 能把对象插到链前端「延长作用域链」，现代严格模式已禁用，`catch (e)` 的 `e` 只是块级变量——这个说法已成历史但面试要能对上号。

### 4. 面试官：作用域链和原型链有什么区别？

**回答**：一个查标识符、一个查属性，四点对照：

| | 作用域链 | 原型链 |
| --- | --- | --- |
| 查找什么 | 标识符（变量名、函数名） | 对象的属性 |
| 沿着什么 | 词法环境的 `outer` 引用 | 对象的 `[[Prototype]]` |
| 何时确定 | 函数定义时（词法） | 对象创建 / 原型连接时 |
| 未命中的结局 | `ReferenceError` | `undefined`（不报错） |

两条链会叠加工作：`obj.a` 先沿作用域链找到 `obj` 这个标识符，再沿 `obj` 的原型链找属性 `a`。原型链那侧的完整机制在[原型与原型链题](/javascript/02-prototype-and-prototype-chain)。

### 5. 面试官：「局部变量比全局变量访问快」这话还对吗？

**回答**：知识点层面成立——局部在链头、全局在链尾，这是它的出处。但现代引擎有内联缓存和环境的形状优化，命中的访问都接近一次指针解引用，**实测差距可忽略**——当知识点答可以，当优化手段写代码没必要（原型链那题的加深理解讲过同样的结论）。

### 6. 面试官：IIFE 当年为什么流行？

**回答**：在没有块级作用域和模块的年代，`var` 只有函数级作用域——IIFE 用「函数作用域」把私有变量包起来、只暴露少量接口，避免标识符堆到全局环境。`let / const` + ESM 出现后，这个用途消失了；剩下的场景主要是「立即执行一段逻辑并拿返回值」（如单例初始化 `const app = (() => {...})()`）。

## 加深理解

### ES3 的 [[Scope]] 和 ES6 的 [[Environment]] 是一回事吗

指同一机制的两代建模：ES3 说函数创建时把父级变量对象链存进内部属性 [[Scope]]，调用时创建自己的 AO 放到链前端；ES6 说函数创建时保存定义时的词法环境到 [[Environment]]，调用时新环境的 outer 指向它。表述不同，结论一致——**链的外层部分在定义时冻结，调用只补最前面一节**。这也是「改变函数定义位置就改变它的作用域链」的原因。

### for 循环的 let 到底创建了几个环境

每轮迭代一个，共 N + 1 个（外加循环体外的那个块环境登记 i 的初值更新）。每轮环境里保存当轮的 i，异步回调闭包引用的是「自己那轮」的环境，所以输出 0、1、2。var 只有一个函数级环境，N 个回调共享同一个 j，回调执行时循环早已结束，j 已是 3。这是「作用域链 + 闭包」交叉出题率最高的一个场景。

### 为什么 with 被禁用

`with (obj) { ... }` 把 obj 插到作用域链最前端，块内的每个标识符都可能是 obj 的属性——引擎无法在解析期确定标识符绑定到哪一节，只能关闭该函数的静态优化。且「属性当变量」让代码语义含混（obj 上有没有这个属性决定了行为）。严格模式直接语法报错，`catch (e)` 的历史待遇也被块级作用域收编。
