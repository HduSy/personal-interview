# 09. == 和 === 有什么区别？

## 高频问答

### 1. 一句话区别

- **`===` 严格相等**：类型不同直接 `false`，**不做任何转换**；同类型比值（对象比引用）；
- **`==` 宽松相等**：类型不同时先做**隐式类型转换**，转换后再比。

实践结论先行：**代码里一律写 `===`**；`==` 需要会读会推（老代码、面试题），以及一个惯用例外 `x == null`。

### 2. `==` 的转换规则主干

类型不同时按这几条走（能背主干就够推所有题）：

1. **`null == undefined` 为 `true`**，且它们**不等于其他任何值**（`null == 0` 是 `false`！）；
2. 数字 vs 字符串：**字符串转数字**再比；
3. 布尔参与：**布尔先转数字**（`true → 1`、`false → 0`），再按前面的规则继续；
4. 对象 vs 原始值：对象先转原始值（`ToPrimitive`：先 `valueOf` 后 `toString`），再比；
5. `NaN` 参与的任何 `==` 都是 `false`。

经典结果速查：

| 表达式 | 结果 | 推导 |
| --- | --- | --- |
| `1 == '1'` | `true` | `'1'` → 1 |
| `'' == false` | `true` | 都转 0 |
| `[] == false` | `true` | `[]` → `''` → 0，`false` → 0 |
| `[] == ![]` | `true` | `![]` → `false` → 0，`[]` → `''` → 0 |
| `null == 0` | `false` | `null` 只与 `undefined` 相等 |
| `null == undefined` | `true` | 规则特判，双向唯一 |

### 3. `===` 的规则与两个特例

同类型比值：原始值比值，对象比**引用**（地址）；类型不同直接 `false`。两个特例在 `==` 下也一样：

1. **`NaN` 不等于任何值包括自身**——`NaN === NaN` 为 `false`（IEEE 754 的规定）；判 NaN 用 `Number.isNaN()`；
2. **`+0 === -0` 为 `true`**——要区分它们用 `Object.is(+0, -0)`（`false`）。

`Object.is` 是第三种相等：与 `===` 唯二的差别就是 `Object.is(NaN, NaN)` 为 `true`、`Object.is(+0, -0)` 为 `false`。

### 4. 工程建议与高频追问

**为什么默认 `===`？** `==` 的转换规则表没人记得全，行为违反直觉（`[] == ![]` 居然 true），维护成本大于收益；ESLint 的 `eqeqeq` 规则默认就是禁 `==`。**唯一惯用的 `==`**：`x == null` 一次判断「null 或 undefined」两个空值。

**`[] == ![]` 完整推一遍**：`![]` 先求值——`[]` 是真值（对象都真值），得 `false` → 转数字 `0`；`[]` 转原始值得 `''` → 转数字 `0`；`0 == 0` → `true`。

**Map / Set 的键用什么相等？** `SameValueZero`：同 `Object.is`，但 `+0` 和 `-0` 视为相等——所以 `NaN` 可以作 Map 的键（与 `===` 行为不同），`-0` 和 `+0` 是同一个键。

## 加深理解

### ToPrimitive 转换的完整顺序

对象转原始值时带一个「提示（hint）」：`default` / `number` / `string`。顺序：**有 `Symbol.toPrimitive` 方法先用它**（传 hint）；否则按 hint 调 `valueOf` → `toString`（number 提示）或 `toString` → `valueOf`（string 提示）；相等比较走 `default` 提示，行为等同 number。数组 `valueOf` 返回自身（不是原始值）被跳过，所以 `[]` 转出来的是 `''`（空数组 join）、`[1,2]` 转出来的是 `'1,2'`。

### null == 0 为什么是 false

直觉上 `null` 像 0，但宽松相等对 `null / undefined` 只写了一条特判：两者互相相等、与其它一切不相等，**根本不走数字转换**。这是规范里「null 就是不等于数字」的显式规定，不是漏写。

### NaN 为什么不等于自己

IEEE 754 浮点标准规定 NaN 表示「非确定的值」，两个 NaN 背后的位模式可能来自不同运算，判定相等没有意义，于是比较运算恒 false。副作用：`[NaN].indexOf(NaN)` 找不到（用 ===），`includes` 找得到（用 SameValueZero）——数组方法内部相等语义不同，排查这类 bug 时先想到这一层。

### 全量对照表：两边都为真 / 只有 == 真 / 都为假

**两边同真**——同类型比值相等（含位级特例：`+0` 与 `-0` 相等、两个 BigInt 按数值比）：

| x | y | `==` | `===` |
| --- | --- | --- | --- |
| `undefined` | `undefined` | ✅ | ✅ |
| `null` | `null` | ✅ | ✅ |
| `true` | `true` | ✅ | ✅ |
| `false` | `false` | ✅ | ✅ |
| `'foo'` | `'foo'` | ✅ | ✅ |
| `0` | `0` | ✅ | ✅ |
| `+0` | `-0` | ✅ | ✅ |
| `+0` | `0` | ✅ | ✅ |
| `-0` | `0` | ✅ | ✅ |
| `0n` | `-0n` | ✅ | ✅ |

**只有 `==` 为真**——跨类型被转换拉平：布尔转数字、对象 ToPrimitive、null 与 undefined 互相特判、BigInt 与数字比数学值：

| x | y | `==` | `===` |
| --- | --- | --- | --- |
| `0` | `false` | ✅ | ❌ |
| `''` | `false` | ✅ | ❌ |
| `''` | `0` | ✅ | ❌ |
| `'0'` | `0` | ✅ | ❌ |
| `'17'` | `17` | ✅ | ❌ |
| `[1, 2]` | `'1,2'` | ✅ | ❌ |
| `new String('foo')` | `'foo'` | ✅ | ❌ |
| `null` | `undefined` | ✅ | ❌ |
| `0n` | `0` | ✅ | ❌ |

**两边都为假**——null / undefined 不与布尔、数字转换；对象比引用，内容相同也是两个对象；NaN 与一切不等：

| x | y | `==` | `===` |
| --- | --- | --- | --- |
| `null` | `false` | ❌ | ❌ |
| `undefined` | `false` | ❌ | ❌ |
| `{ foo: 'bar' }` | `{ foo: 'bar' }` | ❌ | ❌ |
| `new String('foo')` | `new String('foo')` | ❌ | ❌ |
| `0` | `null` | ❌ | ❌ |
| `0` | `NaN` | ❌ | ❌ |
| `'foo'` | `NaN` | ❌ | ❌ |
| `NaN` | `NaN` | ❌ | ❌ |
