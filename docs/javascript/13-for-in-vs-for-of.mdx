# 13. for...in 和 for...of 的区别是什么？

## 高频问答

### 1. 先给答案：一句话核心 + 五条展开

核心一句话：**for...in 遍历「键」，沿原型链挑可枚举的字符串键；for...of 遍历「值」，走的是对象的迭代器**。

**一、拿到的东西不同**。`for (const k in obj)` 拿到的是**键名**（全是字符串）；`for (const v of iterable)` 拿到的是**值**。

**二、数据来源不同**。in 枚举「自身可枚举属性 + **原型链上**的可枚举属性」；of 与属性无关，它调用对象的 `Symbol.iterator` 方法，按迭代器吐出的顺序取值。

**三、适用对象不同**。任何对象都能跑 in（包括数组——但拿到的是 `'0' '1' '2'` 这样的**索引字符串**）；of 只能用于**可迭代对象**：数组、字符串、Map、Set、NodeList、`arguments`、生成器。普通对象没有迭代器，用 of 直接抛 `TypeError`。

**四、顺序保证不同**。in 的顺序规范规定为：整数型键升序在前、其余按插入序——依赖它排序是危险习惯；of 严格按迭代器的产出顺序，数组就是下标序。

**五、控制流能力**。两者都能 `break / continue / return`；of 还有异步版 **`for await...of`**，消费异步迭代器（[ES 新特性题](/javascript/07-es-new-features)里 `Array.fromAsync` 就是建在它之上的）。

口诀：**遍历对象用 for...in（配 `hasOwn` 过滤），遍历数组与可迭代用 for...of；数组不要用 for...in**。

### 2. for...in 侧展开：可枚举、原型链、Symbol 键的例外

in 的筛选条件有三个，少背一个就踩坑：

1. **只列可枚举属性**——`Array.prototype` 上的方法、`Object.prototype` 的 `toString` 都不可枚举，所以平时遍历数组不会看到它们；自己用 `Object.defineProperty(x, 'k', { value: 1, enumerable: false })` 定义的键同样会被跳过；
2. **沿原型链一路列到 null**——继承来的可枚举属性照出不误，所以工程写法必须配过滤：

```js
for (const k in obj) {
  if (Object.hasOwn(obj, k)) { /* 只处理自身属性 */ }
}
```

3. **Symbol 键一律不列**——in 与 `Object.keys` 都只处理字符串键，Symbol 键要用 `Object.getOwnPropertySymbols` 单独拿，两者混着用 `Reflect.ownKeys` 全拿。

### 3. for...of 侧展开：迭代器协议

of 不看属性，只认 **`Symbol.iterator`**：引擎调 `obj[Symbol.iterator]()` 拿到迭代器，然后反复 `next()`，拿到 `{ value, done }`，`done` 为 true 停止。数组、字符串、Map、Set、NodeList、生成器都内置了实现；普通对象没实现，所以报 `xxx is not iterable`。

```js
for (const [k, v] of new Map([['a', 1], ['b', 2]])) {
  // Map 的迭代器产出 [键, 值] 条目，配合解构最顺手
}

// 想用 of 遍历普通对象：先转数组，自身属性、不碰原型链
for (const [k, v] of Object.entries(obj)) { /* ... */ }
```

`Object.entries / values / keys` + for...of 是遍历对象的现代标准答案——比 for...in 干净（不沿原型链、不列 Symbol、顺序确定）。

### 5. 高频追问

**遍历对象到底用哪个？** 首选 `Object.entries(obj)` + for...of：键值对一起拿、只看自身、顺序稳定。for...in 只在「确实要包含继承属性」的反射类场景才有必要。

**数组为什么别用 for...in？** 三个理由连着说：键是字符串索引（做算术前还得转数字）；数组上后来加的**非索引属性**和原型链上的可枚举属性会混进来；顺序规则比下标序复杂。数组遍历的答案就是 for...of 或数组方法。

**`Object.keys` 和 for...in 什么关系？** keys 等于「in 的结果去掉原型链」——只列自身可枚举字符串键。values / entries 同理。所以 keys 的输出永远不用配 hasOwn 过滤。

**给普通对象加上可迭代能力怎么做？** 实现 `Symbol.iterator`（返回带 `next()` 的对象），它就能进 for...of、被展开运算符与 `Array.from` 消费——机制条目里给了最小实现。

## 加深理解

### 什么是可枚举属性

每个属性除了值，还带三个特性开关（存放在**属性描述符**里）：`writable`（可否重写）、`enumerable`（可否被枚举）、`configurable`（可否删除或修改特性）。「可枚举」只决定一件事：**集体枚举时这个属性答不答到**——`for...in`、`Object.keys / values / entries`、`JSON.stringify`、对象展开 `{...obj}` 都只处理可枚举属性。普通赋值和字面量创建的属性默认可枚举；内置原型方法与数组 `length` 默认**不可**枚举——这就是 for...in 不列出 `forEach`、`toString` 的原因。注意不可枚举 ≠ 不可访问：`obj.k` 照常读写，只是枚举类操作看不见。查看用 `Object.getOwnPropertyDescriptor`，创建不可枚举属性用 `Object.defineProperty(obj, 'k', { value: 1, enumerable: false })`，要连不可枚举一起列用 `Object.getOwnPropertyNames` / `Reflect.ownKeys`——`JSON.stringify` 静默丢弃不可枚举属性，序列化突然缺字段时先查这一层。

### 迭代器协议的最小实现

```js
const range = {
  from: 1,
  to: 3,
  [Symbol.iterator]() {
    let cur = this.from;
    const last = this.to;
    return {
      next() {
        return cur <= last ? { value: cur++, done: false } : { value: undefined, done: true };
      },
    };
  },
};

[...range]; // [1, 2, 3] —— 展开运算符、Array.from、for...of 全部可用
```

迭代器协议就两个部件：`Symbol.iterator` 方法返回一个带 `next()` 的对象，`next()` 返回 `{ value, done }`。这也是生成器函数为什么天然可迭代的原因——生成器对象本身就实现了 next。

### 稀疏数组上两者的行为分叉

`for...in` 只列**存在**的索引——`[,,]` 里两个空槽都不会出现；`for...of` 走数组迭代器，每个下标都取值，空槽输出 `undefined`。与数组方法「跳过空槽」的行为对照着记（[数组 API 题](/javascript/10-array-apis)讲过哪些方法跳、哪些不跳）。

### 为什么 for...in 不列 Symbol 键

规范把它定为「只处理字符串键的枚举」：Symbol 从设计上就是「不易被意外枚举」的键——避免第三方代码往原型上挂 symbol 后，所有 for...in 循环被污染。代价就是 symbol 属性天生「半隐形」，必须用 `getOwnPropertySymbols` 显式去拿。
