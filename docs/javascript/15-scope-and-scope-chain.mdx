# 15. 谈谈 JS 的作用域和作用域链

## 高频问答

### 1. 作用域是什么：变量可访问的范围

作用域（scope）是**变量与函数能够被访问的范围**，由代码的书写结构在**定义时**划定。JS 的作用域按形成方式分四种，面试按这个顺序报：

**一、全局作用域**。顶层代码所在的范围，程序任何位置都能访问。浏览器里非模块代码的 `var`、函数声明会挂到全局对象上（`window.x`）；用 `let / const` 声明的顶层变量是全局作用域的，但**不挂在全局对象上**。

**二、函数作用域**。每个函数调用创建独立的作用域——`var` 与函数声明以函数为可见边界，「函数外访问不到函数内的变量」。这是 ES6 之前 JS 唯一的局部作用域。

**三、块级作用域（ES6）**。`let / const` 以任意 `{}` 块为界：`if`、`for`、裸写的大括号都算。**`var` 没有块级概念**——它穿透块，只认函数边界，这是 var/let 最核心的行为差异。

**四、模块作用域（ESM）**。每个模块文件有自己的顶层作用域：模块顶层声明的变量**不是全局变量**，只在本文件可见，对外必须显式 `export`。对比：普通 `<script>` 标签们共享同一个全局作用域，模块们各有一层。

### 2. var / let / const 三条速答（作用域视角）

1. **边界**：var 只认函数；let / const 认块——`{ let x }` 出块即不可见；
2. **提升行为**：var 提升并初始化为 `undefined`；let / const 也提升但**不初始化**，声明前访问抛 `ReferenceError`（TDZ，[执行上下文题](/javascript/04-execution-context-stack)讲过它是创建阶段的登记方式）；
3. **重复声明**：var 允许；let / const 同一作用域内禁止。const 另加「绑定不可重新赋值」一条（对象内容仍可改）。

### 3. 作用域链：查找路径，转发两站

当前作用域找不到标识符时，沿「**内层 → 外层 → …… → 全局**」逐层向外找，这条路径就是作用域链，**函数定义时就已确定**（词法作用域）。就近命中即遮蔽外层、到全局未命中抛 `ReferenceError`。

### 5. 高频追问

**作用域和执行上下文什么关系？** 作用域是**静态的规则**（写代码时确定范围）；执行上下文是**动态的运行实例**（调用时创建、执行完销毁）。一个函数定义一次只有一个作用域链，但每次调用都会新建一份变量环境——「规则一套、实例多份」。

**全局变量有什么坑？** 三连答：非严格模式下不声明直接赋值会**隐式创建全局**；所有代码共享一节作用域链，**命名冲突**风险最高；难以回收。规避：模块作用域天然隔离（现代项目默认），或把代码包进函数 / 块里。

**块级作用域出现后，IIFE 还用来干嘛？** 「造私有作用域」这个历史用途被 let / const 块和模块接管了；IIFE 剩下的场景主要是「立即执行一段逻辑并拿返回值」（如 `const app = (() => {...})()` 单例初始化）。

## 加深理解

### 同一函数多次调用：作用域链共享，环境各建各的

函数的作用域链（指向哪些外层）在定义时冻结，调用 N 次用的都是同一份；但每次调用都会**新建**一个变量环境装本次的参数与局部变量，互不影响——这正是递归里各层 `n` 互不覆盖的原因（[执行上下文题](/javascript/04-execution-context-stack)的沙箱验证过）。区分「链共享」与「环境新建」这两件事，作用域与上下文的关系就彻底清楚了。

### 模块作用域和 script 全局的本质差别

普通 `<script>` 里顶层 `var x = 1` 之后，另一个 script 标签里 `x` 直接可用——它们共享全局作用域，且 `x === window.x`。模块里顶层 `var / let / const` 都**不上**全局对象、也**不跨文件可见**，别的文件要用必须 `import`；模块顶层的 `this` 是 `undefined` 而不是全局对象（[this 题](/javascript/06-this)讲过默认绑定在严格语义下的取值）。这就是「模块天然防全局污染」的机制层解释——作用域多了一层，全局只是它的外层而不是同一个。

### let / const 到底提升不提升

提升。把「提升」拆成两步就没歧义了：**登记**（名字在块创建时写进环境）与**初始化**（拿到 `undefined` 或值）。`var` 两步都在创建阶段完成，所以声明前可访问；`let / const` 完成登记但**不初始化**——块开始到声明语句执行之间是 TDZ，访问即抛 `ReferenceError`。遮蔽实验是最强证据：

```js
let x = 'outer';
{
  console.log(x);   // ReferenceError —— 若内层 let 未登记，这里应打印 'outer'
  let x = 'inner';
}
```

内层 `x` 若没在块创建时登记，查找会命中外层打印 `'outer'`；实际抛错，说明内层绑定已存在并从头遮住了外层。旁证两条：`typeof` 未声明变量安全返回 `'undefined'`，对 TDZ 变量照样抛错（引擎已知道这个名字）；报错文案也不同——未声明是 `xx is not defined`，TDZ 是 `Cannot access 'xx' before initialization`（存在但未初始化）。所以 `ReferenceError` 不是「没提升」的证据，恰是「已登记、未初始化」的守卫行为；老文章说「let 不提升」用的是 var 式狭义定义（提升 = 声明前可访问），与规范口径不同。
