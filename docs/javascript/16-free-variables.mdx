# 16. 什么是 JS 的自由变量？如何理解？

## 高频问答

### 1. 定义：当前作用域未声明、到上层去找的变量

**自由变量：在当前作用域中没有声明、需要沿作用域链到外层作用域去找的变量**。当前作用域里自己声明的变量和参数不算——它们本层就有。

```js
var a = 10;                 // 全局变量

function foo() {
  console.log(a);           // a 在 foo 里没声明 —— 自由变量，沿作用域链在全局找到
}

foo();                      // 10
```

一句话记忆：**本层没有、出门去找的，就是自由变量**。「自由」说的是它不受当前作用域管辖，归属在上层。

### 2. 在哪找：沿定义时的作用域链

自由变量沿**定义时的词法作用域链**逐层向外找——内层 → 外层 → 全局，找到第一个绑定即停，到全局仍未命中抛 `ReferenceError`。为什么是定义处而不是调用处、就近遮蔽与赋值不沿链的规则，在[词法作用域题](/javascript/03-lexical-vs-dynamic-scope)和[作用域链题](/javascript/05-scope-chain)里详细讲过——自由变量就是那条链上的「查不到才出门」的查找。

### 3. 与闭包的关系：自由变量是闭包抓住的东西

闭包 = 函数 + 定义时的词法环境。**内层函数用到的自由变量，正是闭包「抓住」的内容**：外层函数返回后，只要内层函数还引用着这些自由变量，装它们的环境对象就在堆上继续存活——`checkscope` 那个经典例子里（[词法作用域题](/javascript/03-lexical-vs-dynamic-scope)加深理解），`scope` 就是 `f` 的自由变量，也是 `f` 闭包的全部意义所在。

```js
function counter() {
  let count = 0;              // 对内层两个函数而言是自由变量
  return {
    inc: () => ++count,
    get: () => count,
  };
}
const c = counter();
c.inc(); c.inc();
c.get();                      // 2 —— count 是被闭包持有的自由变量
```

### 4. 关键认知：捕获的是「绑定」，不是「快照」

自由变量在**每次执行时**去外层环境取**当前值**——闭包记住的是「变量在哪个环境」，不是「定义那一刻的值」：

```js
let x = 1;
function get() { return x; }   // x 是自由变量
x = 2;
get();                         // 2，不是 1 —— 取的是调用时的当前值
```

最经典的翻车现场是 `for + var` 的回调输出 `3 3 3`：所有回调的自由变量 `i` 解析到**同一个** var 绑定，循环结束值已是 3；`let` 每轮创建新环境、各捕获各的（环境数与机制在[作用域链题](/javascript/05-scope-chain)的加深理解里推过）。

}

function counter() {

  return { inc: () => ++count, get: () => count };
}
const c1 = counter(), c2 = counter();
c1.inc(); c1.inc();
console.log('c1：', c1.get(), '| c2：', c2.get(), '—— 各自独立的环境');

console.log('③ 取当前值，不是快照');
let x = 1;

x = 2;
console.log('x 变了，get() =', get());`}
/>

**「参数和局部变量为什么不算？」** 它们是本层的：参数传进来、局部变量自己声明，查找在本层就结束；自由变量的定义就是「本层没有、要出门找」。

**「自由变量一定解析到全局变量吗？」** 不一定。多数自由变量解析到**中间层**（外层函数的局部变量），只有一路找到全局的才是全局变量；模块化代码里还可能解析到模块顶层变量或 `import` 进来的绑定（见加深理解的 live binding）。

**「引擎里自由变量存在哪？」** 装它们的词法环境是**堆上的对象**，函数通过创建时保存的 `[[Environment]]` 引用找到它——执行上下文出栈后环境仍在，这就是闭包能跨调用存活的原因（[执行上下文题](/javascript/04-execution-context-stack)讲过这根指针）。

## 加深理解

### 「自由 / 约束」这对名字的来源

出自 lambda 演算与形式语言：在一个函数项里，由**本函数的绑定器**（lambda 抽象、参数）引入的变量是约束变量，其余是自由变量——「自由」于本函数的绑定之外。JS 沿用这对术语描述同一件事：参数与 `var/let/const` 局部声明是绑定器，没被本函数绑定却使用了的名字就是自由的。

### 一个环境，多个闭包共享

`counter` 例子里 `inc` 和 `get` 是两个闭包函数，但它们引用的自由变量 `count` 在**同一个**环境对象里——所以 `inc` 改了、`get` 看得见。再对照 `c1` 和 `c2`：两次调用 `counter` 创建了**两个独立环境**，互不可见。「捕获的单位是环境（绑定），不是函数、也不是值」——这一句能解释闭包题库里几乎所有变体。

### import 进来的名字也是自由变量，且是「活绑定」

模块内使用 `import { count } from './m.js'` 后，函数里用到的 `count` 同样是自由变量——解析目标是导入绑定。ESM 的导入是**活绑定（live binding）**：取的是导出模块里那个变量的**当前值**，导出方改了、导入方读到新值；CommonJS 的 `require` 拿到的是**导出时刻的值拷贝**（对象属性除外）。这与第 4 节「取当前值」的语义一脉相承——自由变量永远解析到绑定，绑定的值随时间变化。
