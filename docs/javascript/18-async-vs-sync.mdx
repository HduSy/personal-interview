# 18. 同步和异步有什么区别？异步的意义是什么？

## 高频问答

### 1. 先给答案：一句话区别 + 一句话意义

**区别**：同步任务**排队执行——前一件做完才轮到下一件**，耗时的同步操作会把后面所有代码卡住；异步任务**现在登记回调、立刻继续往下执行**，等事件就绪了再回头执行回调。一句话：同步是「**等结果**」，异步是「**登记、继续、回头处理**」。

**意义**：JS 是**单线程**的，渲染、点击、脚本全挤在一条主线程上。遇到网络请求、定时器这类耗时操作若同步等待，整个页面会冻结。异步把**耗时的事交给浏览器其他模块去办**，主线程继续跑后续代码，结果好了再通知——**界面不卡、I/O 并发**。

### 2. 同步：排队模型

JS 单线程 + 调用栈（[执行上下文题](/javascript/04-execution-context-stack)）：同步任务逐个进栈，**当前任务不结束，下一个进不来**——这就是「阻塞」。现场感最强的例子：一个跑 5 秒的大循环期间，页面点击、动画、渲染全部冻结，因为它们排在循环后面。历史上的同步 XHR 就是这么把页面卡死的，所以被废弃了。

### 3. 异步：登记 → 继续 → 回头执行

```js
console.log('1 起点');
setTimeout(() => console.log('2 定时器回调'), 0);   // 只登记，不等
console.log('3 同步继续');
// 输出顺序：1 → 3 → 2
```

`setTimeout(..., 0)` 都排在所有同步代码之后——异步回调**必须等主线程把栈清空**，才由事件循环从任务队列取出执行（队列与事件循环的完整机制是独立一题，[执行上下文题](/javascript/04-execution-context-stack)里先记「栈清空才轮到回调」这句）。

关键分工：**计时、网络传输这些活不是 JS 干的**——浏览器有专门的模块处理，完成后把回调放进队列。JS 单线程与「异步任务并行推进」不矛盾：**出力的不是 JS，JS 只收结果**。

### 4. 意义展开：三层

**一、界面不冻结**。渲染和用户输入与 JS 共享主线程，同步卡 5 秒 = 页面死 5 秒；异步让主线程始终快速回到渲染和响应上。

**二、I/O 并发**。同时发三个请求，总耗时约等于最慢的一个；同步串行则是三个相加。网络、磁盘这类「等待为主」的操作，并发收益巨大。

**三、单线程下也能「并行」办事**。JS 自己只有一条线程，但耗时任务都在外部并行推进，主线程只处理就绪的结果——单线程照样高吞吐。需要真正的多线程计算时用 [Web Worker](/javascript/01-web-worker)（另一条跑 JS 的线程，与这里的异步调度是两回事）。

setTimeout(() => console.log('C 完成，用时', Date.now() - start, 'ms'), 1000);`}
/>

**「setTimeout(fn, 0) 是立刻执行吗？」** 不是。0 只是「最早可执行时间」，还要等主线程把当前所有同步代码跑完——它常被用作「把这件事推迟到本轮渲染之后」的技巧，而不是「立刻」。

**「JS 单线程为什么还能异步？」** 耗时操作由浏览器的定时器、网络等模块在 JS 线程之外推进，完成后把回调放进任务队列；JS 主线程只负责取出并执行回调。「异步 ≠ 多线程」，它是任务调度方式。

**「异步的代价？」** 执行顺序不再直观，回调层层嵌套难读（回调地狱）——这正是 Promise、async/await 要解决的问题（独立成题）；错误处理也从 try/catch 变成回调参数 / catch 链。

**「同步一定不好吗？」** 不。逻辑本身连续、无耗时的场景用同步最清晰；异步只在**等待**（网络、定时、事件）是主要成本时才有必要。

## 加深理解

### 「阻塞」到底挡住了谁

主线程上排队的除了 JS 还有：**渲染（布局、绘制）、用户输入处理、垃圾回收**。同步任务跑 5 秒，这五者全部排在后面——所以页面既不动也不响应点击。经验阈值：单次任务控制在几十毫秒级，超过用户就能感知卡顿；长任务要么拆成小块（分批处理），要么挪去 Web Worker。

### 定时器为什么「不准」

`setTimeout(fn, 1000)` 只保证**至少** 1 秒后回调可执行：到点后回调进队列，如果主线程正忙（同步任务未跑完），它还得继续等。所以计时误差 = 主线程阻塞时长。这也解释了嵌套 setTimeout 与 setInterval 的漂移问题——定时器的「到点」与「执行」是两个分离的时刻。

### 同步风格的异步：async/await 没有改变模型

`await` 看起来像同步等待，实际是**暂停当前函数、把控制权还给主线程**，结果就绪后从暂停处继续——主线程全程没有阻塞。这是「写法同步、机制异步」：排队模型和登记回调模型仍然成立，只是登记/恢复由语法代劳。分清「写法」与「模型」，异步的题就不会被各种新语法绕晕。
