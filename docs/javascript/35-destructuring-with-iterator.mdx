# 35. 如何让 var [a, b] = &#123;a: 1, b: 2&#125; 解构赋值成功？

## 高频问答

### 1. 面试官：如何让 var [a, b] = &#123;a: 1, b: 2&#125; 解构赋值成功？

**回答**：直接写会抛 **TypeError: … is not iterable**——数组解构要求右侧是**可迭代对象**，普通对象没有迭代能力。让它成功的办法：**给这个对象实现 `Symbol.iterator` 方法**，把它变成可迭代的：

```js
const obj = {
  a: 1,
  b: 2,
  *[Symbol.iterator]() { yield* Object.values(this); }
};

var [a, b] = obj;   // a = 1, b = 2
```

生成器写法最简洁；等价的手写版、以及不改对象本身的 Proxy 方案，后面几问展开。这题表面考解构，实际考的是**迭代协议**掌握得透不透。

### 2. 面试官：为什么会报错？数组解构到底在做什么？

**回答**：两种解构的工作方式完全不同：

- **对象解构**（`var { a, b } = obj`）按**属性名**取值——右侧只要有对应属性就行，任何对象都能解；
- **数组解构**（`var [a, b] = x`）按**迭代**取值——引擎调用右侧的 `Symbol.iterator()` 拿到迭代器，反复调 `next()`，把每个 `{ value, done }` 里的 value 依次赋给左边的变量，done 为 true 时停止。

所以数组解构要求的不是「像数组的东西」，而是「实现了迭代器协议的东西」。普通对象没有 `Symbol.iterator`，第一个动作就失败了；字符串能数组解构（`var [c] = 'ab'` 得 `'a'`）正是因为字符串实现了这个方法。

### 3. 面试官：写出完整的实现。

**回答**：两个等价版本：

```js
// 版本一：生成器方法（推荐）
const obj = {
  a: 1,
  b: 2,
  *[Symbol.iterator]() { yield* Object.values(this); }
};

// 版本二：手写 next 迭代器——等价，只是更显式
const obj2 = {
  a: 1,
  b: 2,
  [Symbol.iterator]() {
    const values = Object.values(this);
    let i = 0;
    return {
      next: () => i < values.length
        ? { value: values[i++], done: false }
        : { value: undefined, done: true }
    };
  }
};
```

两个细节：**迭代顺序就是 `Object.values` 的顺序**（对象属性枚举规则，见加深理解）；**解构的变量数多于值时多的取 undefined**——`var [a, b, c] = obj` 得 `1, 2, undefined`，迭代器 done 后剩余变量不再取值。完整现场：

### 4. 面试官：不想修改对象本身，能做到吗？

**回答**：能，用 **Proxy 拦截 `get`**：数组解构取迭代器时会读 `obj[Symbol.iterator]`，Proxy 的 get trap 在这个属性名上返回一个迭代器函数，原对象一个字节都不用动：

```js
const raw = { a: 1, b: 2 };

const [a, b] = new Proxy(raw, {
  get(target, prop) {
    if (prop === Symbol.iterator) {
      return function* () { yield* Object.values(target); };
    }
    return target[prop];
  }
});
// a = 1, b = 2
```

实用主义的补一句：真实项目里不会为解构给业务对象挂迭代器——`var [a, b] = Object.values(obj)` 一行就够。但那就改变了右侧，不再是这道题的语义；面试答 Proxy 是展示你理解「解构只依赖 `get` 迭代器这一个行为」，其余都可以拦截。

### 5. 面试官：这题背后考的迭代协议是什么？

**回答**：两份协议配合：

- **可迭代协议**：对象有 `Symbol.iterator` 方法，调用返回一个迭代器——「能不能被迭代」的准入条件；
- **迭代器协议**：那个返回值带 `next()`，每次调用返回 `{ value, done }`，done 为 true 结束——「怎么逐步给值」的执行约定。

数组解构、for...of、展开运算符 `[...x]`、`Array.from`、`new Map(iterable)`、`Promise.all(iterable)` 全都消费同一套协议——给对象实现了 `Symbol.iterator` 之后，这些能力它一并获得：`for (const v of obj)`、`[...obj]` 都直接能用。所以这题的满分答案要落在协议上：**不是「加了个魔法方法」，而是补齐了语言统一的迭代准入条件**。

### 6. 面试官：能总结一下吗？

**回答**：四种方案对照收尾：

| 方案 | 做法 | 特点 |
| --- | --- | --- |
| 生成器实现 | `[Symbol.iterator]() { yield* Object.values(this) }` | 最简洁，推荐 |
| 手写迭代器 | 返回 `{ next() { … } }` 对象 | 等价但冗长，用于展示协议细节 |
| Proxy 拦截 | get trap 拦 `Symbol.iterator` | 不改原对象 |
| 换右侧 | `Object.values(obj)` | 实用主义，但语义已不是原题 |

## 加深理解

### 迭代顺序：Object.values 不是随便排的

对象属性的枚举规则：**整数样键**（如 `1`、`3`）按数值升序排最前，**字符串键**按插入顺序排后面，symbol 键最后。所以 `Object.values({ 3: 'c', 1: 'a', b: 'x', a: 'y' })` 得 `['a', 'c', 'x', 'y']`——`1`、`3` 升序在前，`b`、`a` 按插入序在后。解构顺序跟这个走，意味着「数组解构对象」拿到的顺序是有确定规则的，但依赖它很脆弱：删一个属性、插入一个整数键都会改变后续位置。

### done 之后的事：值不够给 undefined，多余的 value 被忽略

`next()` 返回 `{ value, done: true }` 时，解构停止，没取到值的变量是 undefined（`var [a, b, c] = obj` 的 c）。反过来，done 为 true 时返回的 value **会被忽略**——所以终止分支里写 `{ done: true }` 或 `{ value: 任意值, done: true }` 结果一样。生成器版本没有这个心智负担：`yield` 完自然结束。

### 为什么对象解构赋值要加括号，数组解构不用

行首的 `[a, b] = obj` 是合法的——规范专门允许数组字面量后面跟 `=` 时按解构赋值解析。行首的 `{ a, b } = obj` 是语法错误：`{` 在语句位置被解析成**块语句**，块后面跟 `=` 就崩了，所以对象解构赋值要套括号 `({ a, b } = obj)`。`var [a, b]`、`var { a, b }` 带声明关键字时都没有这个问题。

### 别把 Symbol.iterator 挂到 Object.prototype

有个更省事的 hack：`Object.prototype[Symbol.iterator] = function* () { yield* Object.values(this) }`——所有对象立刻可迭代，原题一行不改就成功。但这是全局行为污染：所有 `for...of obj` 不再报错（本该暴露的 bug 被吞掉）、所有对象进入 `Array.from`、展开运算符的语义、和任何同样这么干的第三方库冲突。展示思路可以，生产代码不能这么写。
